# latent

**latent = 编码器把复杂数据压成的一串数字，扔掉了冗余、保留了本质，而且能被解码器还原回去。** 中文叫隐变量、隐空间、隐表征。

名字来历是这个词的字面意思「潜在的、藏着的」。波形和像素是可以直接观测的，latent 不是，它是模型在内部自己推断出来的一组数，你测不到它。

**最直观的例子是人脸照片。** 一张 1024×1024 的彩照是 314 万个数字，压成 latent 可能只要 512 个。那 512 个数装的不是像素，是脸型、肤色、表情、发型、光照这些本质属性，解码器能从它们还原出一张几乎一样的脸。压掉六千多倍，扔的是像素级冗余（相邻像素几乎一样、噪点、压缩伪影），留的是身份和结构。

## 为什么能压这么狠

因为真实数据只占整个空间里极小的一块。你随机生成 314 万个 0 到 255 的数当图片看，得到的永远是雪花噪点，试一万亿次也随机不出一张人脸。这块「小区域」在数学上叫流形，这个假设叫**流形假设**。latent 空间本质上就是给这块小区域重新建了一套坐标系。

打个比方，10 万个常用词随便挑 20 个能拼出天文数字种组合，但绝大多数都是乱码，通顺句子只占极小一块。所以你不需要用「20 个词的编号」描述一句话，用「这句话在说什么意思」就够了，后者简洁得多。后者就是句子的 latent。

再比如描述地球表面一个点，用三维 (x,y,z) 是浪费的，用二维 (经度,纬度) 就够，因为点只可能在球面上。

## 关键性质：latent 空间是平滑且有意义的

这条最重要。**两个 latent 之间的中间点，解码出来是一个合理的新数据。**

波形空间没有这个性质。两段波形取平均，得到的不是「介于两者之间的声音」，而是**两个声音同时在响**（会听到明显的拍频）。但如果 latent 编码的是「音高、音色」这类参数，对它们插值再解码，出来的就是一个音高介于两者之间的、单一的新声音。

图像上同样：在两张人脸的 latent 之间插值，会看到一张脸平滑地变成另一张，中间每一帧都是合理的人脸；在像素空间做同样的事，只会看到两张脸鬼影般重叠。

**为什么这对扩散模型生死攸关**：扩散的做法是从一团噪声开始，一步步往「更像真实数据」的方向挪，每一步都是一个中间状态。如果这些中间状态是无意义的垃圾，模型就学不到「往哪儿挪」这个方向。只有在一个「中间点也有意义」的空间里，逐步逼近才说得通。这也是 [[flow-matching]] 那类方法的同一个前提。

## 在音频里具体是多少

以 NaturalSpeech 2 的 codec 为例，16 kHz 音频、下采样率 200：

| | 原始波形 | latent |
|---|---|---|
| 1 秒有多少个位置 | 16000 个采样点 | 80 帧 |
| 每个位置是什么 | 1 个数字（振幅） | 1 个向量（几百维） |
| 每帧覆盖多长 | 0.0625 毫秒 | 12.5 毫秒 |

注意**总的数字个数其实没减少多少**（16000 个标量 vs 80 个几百维向量，量级相当）。真正的收益不在存储变小，在**序列变短**。

因为 Transformer 的自注意力代价是序列长度的平方：直接在波形上跑，1 秒就是 16000² ≈ 2.56 亿；在 latent 上是 80² = 6400。**差四万倍。** 这就是为什么没人直接在波形上跑 Transformer 或扩散，一定要先编码成 latent。

也是因为这个，「帧率」这个数字才那么关键：EnCodec 是 75 Hz，NaturalSpeech 2 的 codec 是 80 Hz，MOSS-Audio-Tokenizer 压到 12.5 Hz。帧率本质上就是在决定序列多长，也就是决定下游模型算不算得动。

## latent 和 token 的关系

| | token（离散） | latent（连续） |
|---|---|---|
| 长什么样 | 一个整数，比如 417 | 一个向量，比如 [0.31, -1.2, 0.05, …] |
| 取值范围 | 码本里的有限个选项 | 连续实数 |
| 怎么得到 | 在码本里查最近邻，返回编号 | 编码器直接输出，或各层码本向量求和 |
| 适合什么模型 | 语言模型（softmax 从词表挑） | 扩散 / flow matching（在连续空间移动） |

**关键是它们常常来自同一个 codec。** 波形过编码器再过 RVQ，得到各层的量化向量。取**各层编号**就是 token（VALL-E 要这个），取**各层向量的和**就是 latent（NaturalSpeech 2 要这个）。同一段音频，同一个 codec，想要哪个取哪个。

所以「用了 RVQ」不等于「是离散表示」，要看它最后拿走的是编号还是向量。NaturalSpeech 2 自己就承认，要得到连续向量根本不需要量化器，用 autoencoder 或 [[vae]] 就行，它用 RVQ 只是为了省内存和加一个正则损失。详见 [[audio-tokenizer]]。

## 几个容易混的词

- **latent vector** 是 latent 空间里的一个具体的点，**latent space** 是所有可能 latent 组成的那个空间。
- **embedding** 通常指查表得到的向量（token id 查出一个向量），latent 强调编码器算出来的。两者经常混用，不必较真。
- **feature** 泛指网络中间层的任何输出，范围更广；latent 特指压缩过、且能解码回原数据的那种。
- **representation** 是最泛的说法，latent 是它的一种。
- **bottleneck** 是网络里最窄的那一层，latent 通常就产生在这里。

## latent diffusion

就是**在 latent 空间做扩散，而不是在原始数据空间做**。图像领域最有名的是 Stable Diffusion，先用 VAE 把 512×512 压成 64×64 的 latent，在 latent 上扩散，最后解码回图像。NaturalSpeech 2 是音频版的同一件事。动机就是上面算的那笔账：省算力。

**一句话总结**：latent 是编码器压出来的一串数字，它省算力（序列大幅变短）、去冗余（扔掉感知上不重要的细节），而且空间平滑有意义（中间点也是合理数据）。最后这条是 [[diffusion]] 这类逐步逼近的生成方法能工作的前提。
