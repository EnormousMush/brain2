# ontology model

**一句直觉：数据库之上的一层「语义 schema」，不是神经网络**

中工互联的「工业本体模型」，本质是数据库之上的语义 schema 层（本体论工程，技术栈类似 RDF+OWL，数学基础是描述逻辑），它不是神经网络。核心是定义「对象-关系-动作」三元组，比如对象是设备/BOM 项、关系是「设备属于产线」、动作是「触发告警」。

**它解决什么问题**

工厂里 ERP/MES/SCADA 一堆异构系统，同一个实体在不同系统里字段名都不一样（equipment_id vs machine_no）。本体模型把这些不同字段映射到统一的 class，解决「系统间没有统一语义、互相不通」的问题（典型案例见 [[bom]]）。

上层的 LLM 不直接去读原始 SQL 库，而是通过标准 API 查询这层语义图。这样能大幅减少 LLM 因为不懂工厂专属业务逻辑而产生的幻觉，思路上属于 neuro-symbolic（用符号 AI 的显式结构，弥补神经网络的模糊推理）。

**落地和趋势**

它常以 ISA-95（企业-车间-现场三层集成标准）为骨架，而不是从零造标准，这也是能快速覆盖多个工业门类的原因。未来趋势是从专家人工定义走向 AI 自动发现新实体新关系（本体自学习），从单企业本体走向行业级标准库。

**护城河判断**：通用大模型能力趋同得很快，单纯「会推理」不再是壁垒。真正值钱的是领域专属、干净、带因果结构的私有数据，以及本体/语义标准的话语权，谁先把行业本体标准定下来，谁就控制了这个领域的数据接口，这比在模型层面竞争更持久。

**一句话总结**：工业本体模型是架在异构数据库之上的统一语义层，用「对象-关系-动作」把碎片字段接通、给 LLM 一个抗幻觉的查询入口，其长期壁垒在私有因果数据和标准话语权，而非模型本身。
