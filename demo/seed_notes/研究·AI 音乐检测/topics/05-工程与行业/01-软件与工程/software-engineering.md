# software engineering

**一句直觉：安全改造一个「活着的系统」的通用剧本**

这份笔记是一套改造在跑的系统时不出事的通用剧本，六条：

- no big-bang refactor：切小步、每步都可回退，不要一次性大改。
- 刻意让风险曲线前易后难：等价变换放前面、改行为放最后。因为到最后地基已经稳了、护栏全了、你对系统的理解也最深。
- 回归护栏先行：动刀之前先建基线快照 + 对比工具，让它当「没退步」的证据生成器。
- 爆炸半径锁死：用 feature flag/灰度，只让 pilot 走新路，其余走老路。
- 重构和改功能绝不混在一个改动里：否则出了 bug 分不清是哪边引起的。
- 先用低风险动作建立信任，再去争取高风险的授权。

**顺带一个术语陷阱：两个「回归」毫无关系**

工程语境的「回归 regression」指功能退步变坏（regression testing/回归护栏 = 确认新改动没让原本能用的东西坏掉）。它和统计的「回归」完全无关，后者指预测连续数值的任务、对立 classification，名字源于 19 世纪 Galton 的 regression toward the mean 这个历史包袱，和「预测数值」本身没有语义关联。两个词拼写相同、含义无关，只能靠上下文区分。

这套剧本和 [[software-design]] 的 correct-by-construction 是互补的：一个讲怎么设计新系统，一个讲怎么改造旧系统。

**一句话总结**：改活系统的剧本核心是「小步、可回退、护栏先行、风险后置、重构与改功能分开」，外加记住工程的「回归 = 退步」和统计的「回归 = 预测数值」是同名不同物。
