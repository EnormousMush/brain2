# frontend

**HMR：改哪换哪，不刷整页**

HMR（Hot Module Replacement）是开发时的热替换机制：你改了某个组件，它只把那个组件换掉，而不是刷新整个页面。好处是页面当前的状态能保住，比如你填了一半的表单不会被清空，改完代码接着填。

**React 的心智：UI 是组件（函数），数据一变就重渲染**

React 把界面拆成一个个组件，本质就是函数。数据变了，对应组件就重新渲染一遍。组件本身默认是「无记忆」的纯函数，要给它加状态或副作用，就靠 Hook：useState 管状态、useRef 存引用、useEffect 处理副作用。

**Hook 的死规矩：必须在函数顶层、按固定顺序调用**

Hook 有一条硬规矩：只能在组件函数的顶层调用，不能放在条件判断或 return 之后。原因是 React 靠「你是第几个 hook」来认这个状态是谁的，它内部就是按调用顺序排了个队。你要是把某个 hook 藏在 if 里，某次渲染走了、某次没走，hook 的数量和顺序就变了，React 一对不上号就报错。所以它是「靠位置认身份」，不是靠名字。

这个设计和 [[software-design]] 里 single source of truth 的精神是相通的：状态只在一处声明，其余地方引用，别让同一份信息散落成多个可能打架的副本。

**一句话总结**：React 把 UI 当成「数据 → 组件函数 → 渲染」的映射，Hook 用调用顺序给组件挂状态，所以顺序不能乱；HMR 则让你改代码时把这套状态原地保住。
