# cloud security

**① 各类日志各看一个角度

云上出了安全事,你得有"监控探头"。不同日志源各管一类**可见性**,谁也替不了谁:

- **CloudTrail** → 操作审计:**谁调了哪个 API**(操作层面的"监控录像")。
- **VPC Flow Logs** → 网络流量:谁和谁在通信、流量多大。
- **IAM** → 身份权限:谁有什么权限。
- **S3** → 数据访问:谁动了哪个存储桶。
- **WAF** → Web 攻击:挡 SQL 注入、XSS 这类打网站的攻击。
- **EC2** → 主机层:虚拟机内部发生了什么。

核心思路:**每个探头只看一个切面**,合起来才是全景。

---

**② MITRE ATT&CK:攻击手法的标准词典

ATT&CK 是把**真实攻击者用过的战术、技术**系统性编号的**标准知识库**。写检测规则时对着它写,好处是:**覆盖面对标已知的真实手法,不容易漏**。相当于有一本"坏人常用招式大全",你照着这本布防,而不是自己瞎猜攻击者会怎么打。

---

**③ 关联分析:检测的灵魂**

这条最关键。**单看一条日志,往往什么事都没有**:一次登录、一次 S3 访问、一次外发流量,单独看都正常。

但**串起来就露馅**了:异常登录 + 访问了陌生 S3 桶 + 大流量往外发——这三件事连成一条线,就是典型的**数据窃取链**。

**跨数据源把这些点连成线,就叫关联分析**,而连线的依据正是 ATT&CK 框架(它告诉你哪几步凑一起构成一次完整攻击)。这就是为什么第①条那些分散的日志源必须合看——**价值不在单条,在关联**。

---

**④ SOAR:检测到之后自动处置

**SOAR = Security Orchestration, Automation and Response**(安全编排、自动化与响应)。检测到事件后,按**预设的 playbook(处置剧本)自动动手**:禁用被盗的凭证、隔离出问题的实例、推送告警——**秒级完成,不用等人**。

意义:攻击是秒级的,靠人工响应太慢,SOAR 把"发现→处置"这一段自动化,抢时间。

---

**⑤ 托管 SOC 到底卖什么

一句大实话:**托管 SOC 卖的是咨询 + 运营服务,不是什么独家技术。** ATT&CK、SOAR、各类日志源**全是行业标准组件**,谁都能买到。

那价值在哪?在**整合好 + 规则调好 + 配人盯着 + 加上威胁情报**。就像食材超市都有,但你付钱请大厨,买的是他把菜配好、火候调对、还盯着灶台。托管 SOC 的钱花在"运营"上,不在"零件"上。
