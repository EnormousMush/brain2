# rag

**一句直觉：给模型一场开卷考试**

RAG（Retrieval-Augmented Generation，检索增强生成）解决两个硬伤：窗口装不下海量/私有文档，以及模型训练定型后就不知道最新或私有的信息。它的逻辑跟人开卷考试一模一样，三步：检索（拿问题去外部资料库搜最相关的片段）、增强（把搜到的原文拼到问题前，组成加长提示）、生成（喂给 LLM 让它基于资料回答）。

**好处和检索机制**

好处是省窗口、能用私有/最新数据、减少幻觉（有原文垫着且可溯源）、更新资料只改库不用重训。检索通常是语义检索：事先把资料切块、每块转成向量存进向量数据库，问题也转成向量，找最接近的几块（向量接近约等于语义相近），比关键词搜索聪明，因为匹配的是意思而非字面。

**和 attention 是接力，不是竞争**

RAG 和 [[attention]] 是接力关系：窗口外「找相关信息」这件事由 RAG 显式做（先搜再塞），窗口内的精细理解仍交给 attention。打个比方，RAG 从大海里捞出几瓢相关的水，attention 负责把这几瓢水喝明白。

**更本质的看法：它只是「上下文管理」的一种实现**

RAG 不是唯一手段，它只是「上下文管理」这个大问题下的一种具体做法。并行的其他思路还有：长 context window（暴力塞更多进 prompt）、[[agent-memory]] 这种显式记忆模块（存结构化状态，而不是非结构化的文本 embedding）、context 压缩/摘要（定期总结老对话腾空间）、KV cache 管理（更底层的推理缓存工程）。世界模型里的长程记忆也在往这个方向靠（见 [[world-model]]）。

**一句话总结**：RAG 是「检索→增强→生成」的开卷考试式方案，用向量语义检索把窗口外的相关信息捞进来交给 attention 理解，本质是上下文管理这一大类问题里的一种实现。
