# dpo

**先垫一句背景:RLHF 有多麻烦**

传统 RLHF 对齐分三步:①收集人类偏好数据 → ②**训一个 reward model(RM)**给回答打分 → ③用 **RL(PPO)**让语言模型去最大化这个分数,同时用 KL 约束别跑太远。麻烦在于:要**额外训一个 RM**、要**跑 RL**(采样、打分、更新,又慢又不稳)。DPO 的野心就是——**把这一整套砍掉。**

---

**① 核心洞察:语言模型自己就是个隐藏的 reward model(7-10)**

这是全部魔法的源头。数学上有个已知结论:**"KL 约束下的 reward 最大化"这个问题,有一个闭式最优解**:

```
π(y|x) = (1/Z(x)) · π_ref(y|x) · exp(r(x,y)/β)
```

不用管细节,关键是**这个式子可以反解出 reward**:

```
r(x,y) = β·log[π(y|x)/π_ref(y|x)] + β·log Z(x)
```

看右边——reward 竟然可以**用"策略模型 π 和参考模型 π_ref 的概率比值"直接表示出来**!换句话说:

> **你的语言模型本身,就隐式地已经是一个 reward model 了。** 不需要另外训一个 RM。

那个讨厌的 `log Z(x)`(配分函数,极难算)怎么办?**它只依赖 x,不依赖具体回答 y**。所以当你比较"回答 A vs 回答 B"做**差**的时候,它俩的 `log Z(x)` **完全一样,直接抵消**。这就是整个 DPO 成立的关键——**那个算不出来的麻烦项,在做差时自己没了。**

---

**② DPO loss:退化成一个加权二分类

把上面的 reward 表达式代进 Bradley-Terry 偏好模型(一个"A 比 B 好的概率"的标准公式),`log Z(x)` 抵消后,整个目标就坍缩成:

```
DPO loss = -E[ log σ( β·log(πθ(y_w|x)/π_ref(y_w|x)) − β·log(πθ(y_l|x)/π_ref(y_l|x)) ) ]
```

y_w = 人类**选中**的好回答(winner),y_l = 被**拒绝**的差回答(loser)。

看着吓人,本质极简——**它退化成了一个加权二分类问题**:让模型给"好回答"的相对概率高于"差回答"。

好处一口气全来:

- **不用采样、不用跑 RL**;
- **只需要两个模型**:一个在训的 **Policy(πθ)** + 一个冻住的 **Reference(π_ref)**;
- 连 RM 都不用单独训了。

还有个优雅的细节——**梯度权重是 σ(r̂_l − r̂_w)**,也就是"**当前模型把这对排序判错的程度**"。**排序错得越离谱的样本,权重越大**,模型优先纠正自己错得最狠的地方。自动把火力集中在最该学的样本上。

---

**③ DPO 的代价,以及后浪们

DPO 不是免费午餐,两个硬伤:

**代价一:off-policy(只能反刍固定数据)。** DPO 只能对着一个**固定的偏好数据集**学,像反刍。它**不能像 RLHF 那样在线探索**——现生成新回答、现打分、现学。少了"自己试错"这条路,上限受数据集限制。

**代价二:概率整体漂移。** DPO 为了拉开 chosen 和 rejected 的**相对差距**,常常**偷懒**——把两者的概率**一起往下压**(反正只要相对差距够大就行)。结果导致**输出分布整体漂移**,可能变得奇怪。

**补洞的后浪们**:**IPO / KTO / SimPO / ORPO** 各自在补这些漏(比如 SimPO 去掉参考模型、ORPO 把 SFT 和对齐合一)。

**另一条路 GRPO**(DeepSeek R1 的基础):**干脆回到 RL,但砍掉 Critic**。做法很聪明——对同一个 prompt **采样 G 个回答**,用**组内 reward 的均值/标准差**当 baseline 来算 advantage(谁高于平均就是好),省掉了 PPO 里那个又贵又难训的 Critic 网络。
