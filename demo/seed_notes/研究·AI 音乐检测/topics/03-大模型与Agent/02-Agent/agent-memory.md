# agent memory

 **1. 两种长期记忆：语义 vs 情景**

- **语义记忆**：去掉了时间地点的**干事实**。"用户喜欢 lo-fi"——回答的是"我知道什么"。像一本字典。
- **情景记忆**：带着"那一次、当时、结果怎样"的**具体经历**。"上次给他推 lo-fi 歌单，他很满意"——回答的是"我经历过什么"。像一本日记。

为什么情景记忆重要？因为它让 agent 能**从成败中学习**，而不只是攒一堆偏好标签。这是"从经验中学习"的技术内核——它记得哪次做法成了、哪次砸了。

---

**2. 情景记忆怎么运作：四个环节**

一条经历叫一个 **episode**，结构大概是 `{当时情境 context, 做了什么 action, 结果如何 outcome, 元数据}`。

1. **写入**：让 LLM 把一段对话轨迹总结成上面这种结构化格式。
2. **存储**：存进向量库。关键细节——**只对 context 部分做 embedding**（因为将来检索是"拿现在的处境，去找过去相似的处境"），而时间、成败、任务类型这些**结构化字段当作可过滤的标签**。
3. **检索**（灵魂所在，见下）。
4. **注入**（见第 4 点）。

**检索三维打分**——不是只看"像不像"，而是三个维度加权重排：

- **相似度**：当前处境 vs 历史处境，像不像。
- **时近性 (recency)**：越近发生的越重要，老记忆按时间衰减。
- **重要性**：失败的、结果特别显著的经历，更该被翻出来提醒。

这套 "相似度 × 时近性 × 重要性" 是斯坦福 **Generative Agents（AI 小镇）** 论文提出来的经典范式，现在基本是行业默认做法。

---

**3. 注入：怎么把记忆用上**

把检索到的 episode **压缩成一小段摘要**，拼进这次的 prompt 里，喂回给模型。注意——**没有改模型的任何权重**，纯靠"塞进上下文"来影响这次的决策。这就是 in-context learning（上下文内学习）。模型本身还是那个失忆的模型，只是这次多看了几眼小抄。

---

**4. 真正落地会踩的四个坑**

**坑一：记忆膨胀。** episode 无限涨，检索越来越慢、噪音越来越多。解法是**遗忘/巩固机制**：定期把一堆相似的 episode 合并、蒸馏成更抽象的语义记忆。类比人睡觉时大脑做记忆固化——把零碎经历整理成规律。

**坑二：抽取质量是天花板。** 如果 LLM 总结 episode 时抓错了重点，后面检索再准也白搭。**垃圾进，垃圾出。**

**坑三：错误经验会固化。** 一次失败如果**归因归错了**（把成功当失败、或搞错了失败原因），以后会被反复调出来误导决策。所以需要**可靠的结果信号**——明确的"成功/失败"标签，比模糊的用户反馈靠谱得多。

**坑四："什么算相似"很难定。** 判断"相似情境"的**粒度**：定得太粗，召回一堆不相关的;太细,该召回的召不回。只能针对具体任务慢慢调。


**5.. 动作 DSL 与写操作安全**

- **Op DSL**：agent 不直接调底层 API，而是先用 JSON 描述一个动作，比如 `{"type":"rename"}`，交给运行时统一处理。这样一层间接，就解锁了 **simulate（模拟）/ 批量确认 / diff（看改动）/ 回滚** 这些能力。
- **simulate → execute**：写操作分两步——先**干跑**一遍预检有没有冲突，没问题再**真跑**。通用的"写操作安全两步协议"，防止一下子把东西改坏。
- **invariant（不变量）**：有些硬规则代码没法自动兜住，**必须用 prompt 明确写给 agent**，比如"绝对不能删 X"。原话说得很妙——**好的 agent prompt，是工程师踩坑之后攒出来的判例法**（吃一堑长一智，写进 prompt）。
