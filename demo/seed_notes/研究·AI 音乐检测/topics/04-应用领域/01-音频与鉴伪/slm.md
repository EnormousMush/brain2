# slm

**一句直觉：让一个模型直接听懂语音、直接说出语音，中间不塌缩成文字**

SLM（Speech-Language Model，语音语言模型）想替掉的是传统的**级联**方案：你说话 → ASR 转成文字 → LLM 想 → TTS 念出来。级联的毛病在于中间两次都塌缩成纯文本，你说话时的情绪、语气、犹豫、重音在 ASR 那一步全丢了，LLM 也没办法控制输出的语气。SLM 的做法是把语音也变成 token，和文本 token 交错排进同一个序列，喂给同一个 decoder-only [[transformer]]。模型有两个输出头：language head 预测文本 token（可以从预训练 LLM 直接继承），speech head 预测语音 token（词表不同，只能随机初始化从头学）。

**两条路线：谁当主体**

- **speech-centric**：以成熟的语音生成系统为主体（CosyVoice、Seed-TTS 这类），LLM 只是被塞进去当条件上下文。类比是一个专业播音员配一个编剧，播音员念稿功力一流但只会照稿念，编剧满肚子学问却必须先落成文字才能传给他。语音质量高，但 LLM 的世界知识和推理能力渗不进「说」这个动作。
- **LLM-centric**：以 LLM 为主体，扩充它的词表让它直接吐语音 token。类比是不请播音员了，直接教编剧开口说话。理论上能吃到 LLM 的意图理解、指令跟随、规划决策，代价是他刚学说话，口齿不清。

**LLM-centric 的核心瓶颈是跨模态对齐**

对齐的意思很具体：LLM 内部只有一个表示空间，文本 token 和语音 token 的 embedding 都活在里面，所谓对齐就是让「苹果」这个文本 token 和「念苹果那段音频对应的语音 token」在这个空间里彼此接近、能互相预测。

这件事几乎完全由 [[audio-tokenizer]] 决定，所以那边的耦合 / 半解耦 / 全解耦之分在 SLM 里被放得特别大：耦合表征下同一个音素换个人说就换一批 token id，模型得从一团混乱里自己剥离出「这个音素怎么念」这个信号；解耦表征下语义 token 对说话人不变，对应关系近乎一对一，一学就会。声学细节 token 和文本本来就没有对应关系，也就不需要对齐，交给 LLM 的过参数化去单独建模即可。这套「把好学的部分留给对齐、把难学的部分隔离出去」的分工，是 LLM-centric 路线目前最有效的设计原则。同一个道理在 [[multimodal]] 那边是 CLIP 式的双塔对比对齐，这里换成了词表层面的对齐。

**第二个瓶颈是信息密度失配**

一秒语音要几百个 token（比如 80 帧/秒 × 3 层 RVQ = 240 TPS），而一秒说话最多传递 20 个文本 token 的信息量，差十几倍。一边稀一边稠，对齐难学，而且生成一秒语音要花远超一秒的时间。

一类解法是 **MTP（multi-token prediction，多 token 预测）**：把相邻 g 个语音 token 打成一组，用同一个 hidden state 一次性全部解码出来。speech head 从 2D 矩阵扩成 3D 张量（第三维大小 g），损失取组内平均，输入侧把 g 个 embedding 拼接后过一个 MLP 降采样成一个向量。效果是反直觉的：token rate 从 240 压到 20（12 倍加速），WER 不降反升地从 6.07 变好到 3.01，代价是 UTMOS 从 3.93 掉到 3.67。说明信息密度对齐本身就是收益，不只是省算力。另一类解法是从 tokenizer 侧下手，直接训练低帧率的 token（CosyVoice 2 的 FSQ token、MOSS 系列的 12.5 fps）。前者是事后打包，后者是事前压缩，哪种更优目前没有定论。

**音色应该是全局条件，不是每步维持的状态**

这条是 SLM 里最能迁移出去的经验。耦合表征下音色弥散在所有 token 里，模型必须连续几百步都恰好挑中带目标音色的 token 才不漂移，而采样本身就带随机性，走着走着就飘了。把音色抽成一个向量放在上下文最前面（speaker-aware 生成），音色就从「需要全程维持」变成「一次性指定」，SIM 能从 0.47 提到 0.60，同时 UTMOS 和 WER 一起变好，因为模型省下来的容量回馈给了内容和音质。歌声转换里的音色泄漏问题，本质上是同一个矛盾换了个名字。

评价 SLM 通常同时看 WER、SIM、UTMOS、SR 四个数，它们量的是四件不同的事而且会互相打架，细节见 [[evaluation-metrics]]。

**一句话总结**：SLM 把语音变成 token 塞进 LLM 的词表，从此听和说不用绕道文字；它的成败取决于表征怎么切（解耦程度）、信息密度怎么对齐（帧率或 MTP）、以及哪些属性该被抽成全局条件（音色）。
