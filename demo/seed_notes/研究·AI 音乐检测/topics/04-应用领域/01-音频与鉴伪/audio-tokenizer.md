# audio tokenizer

**① RVQ:层层逼近的压缩

先说地基 **VQ(向量量化)**:准备一本"码本"(codebook,一堆预设的代表向量),来一个连续向量,就在码本里**查最近邻**,返回那个码的**索引**。连续信号就这样被离散成了一个 token。码本多大决定单个 token 装多少信息——1024 个码 = log₂(1024) = **10 bit**。

但单层 VQ 有个问题:想量化得精细,码本就得巨大(码本爆炸)。

**RVQ(残差向量量化)** 的解法很聪明——**层层逼近**:

1. 第一层码本找最近码,记下索引;
2. 算"原向量 − 这个码"剩下的**残差**(没被表示掉的误差);
3. 对这个残差,用第二层码本再量化一次;
4. 再算新残差,第三层继续……层层往下逼近。

**关键好处**:每层用一本**很小**的码本,靠**叠层数**换精度,就能逼近高精度——避免了单层码本爆炸。打个比方:与其用一把有一万个刻度的尺子(码本爆炸),不如用几把粗尺子接力,第一把量个大概、第二把量剩下的零头、第三把再量更细的零头。音频/图像 tokenizer 现在普遍用它

---

**② 帧率与比特率:分辨率的权衡

**token frame rate(帧率)= 采样率 / 下采样率**,它决定**时间分辨率**——每秒切出多少个 token。这里有个逃不掉的取舍:

- **帧率高** → 时间刻画细,但**序列变长**,模型难训(又回到 attention 的 n² 问题);
- **帧率低** → 序列短好训,但**丢时间细节**。

**下采样率**就是连接"采样率"和"帧率"的那座桥——你把原始采样率往下压多少,决定了最终帧率多高。

**bitrate(总信息量)= 帧率 × 层数 × 每层 bit**。三个旋钮:每秒多少帧、RVQ 叠几层、每层码本多少 bit,乘起来就是这个 tokenizer 每秒承载的总信息量。想压得狠(低 bitrate)就得在这三者间取舍。

---

**③ 三类切法:语义和声学要不要分开

除了压缩率,tokenizer 还有个更要命的设计选择:**语义(说了什么)和声学细节(谁在说、什么情绪、什么录音环境)要不要拆开装**。按拆的程度分三档:

- **耦合(coupled)**:不区分,一股脑编进同一批 token。EnCodec、WavTokenizer、BigCodec、StableCodec 属于这类。
- **半解耦(semi-decoupled)**:拿 HuBERT 这类自监督模型的特征当老师,加一项 [[distillation]] 损失,把语义"逼"进 RVQ 第一层,声学细节自然被挤到后面几层。代表是 SpeechTokenizer。这只是软约束,第一层里仍会混进音色。
- **全解耦(decoupled)**:架构级隔离,直接拆成互不相通的子空间(内容、韵律、声学细节),另配一个 timbre extractor 输出全局音色向量。代表是 FACodec。

差别落在哪:耦合表征下,同一个音素由不同人在不同环境说出来,会得到完全不同的 token id,音色信息弥散在所有 token 里,没有哪一层专管它。解耦表征下,语义 token 对说话人不变,音色则变成一个可以一次性指定的全局条件,而不是每一帧都要维持的状态。

---

**④ 重建好不等于好被下游建模

评价 tokenizer 的传统方式是看**重建质量**(编码再解码,听着像不像原声)。但重建任务和下游的生成模型无关,这两件事会分家。

反例很直接:BigCodec 的重建指标优于 FACodec,可两者放进同一个语音语言模型里训练,FACodec 大幅胜出;WavTokenizer 是公认优秀的 codec,进了 SLM 之后合成语音的 WER 高到 89.60、生成成功率只有 0.38,基本不可用。

所以选表征要看它进了下游模型之后好不好学,不能只看 codec 自己的指标。这条在 [[slm]] 那边有展开。
