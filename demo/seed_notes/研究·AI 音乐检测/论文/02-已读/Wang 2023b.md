# Wang 2023b

**Neural Codec Language Models are Zero-Shot Text to Speech Synthesizers（VALL-E）** · Chengyi Wang, Sanyuan Chen, Yu Wu 等 13 人（Microsoft）· arXiv 预印本 · https://arxiv.org/abs/2301.02111 · demo https://aka.ms/valle · 官方未开源

## 它做了什么

**核心改动只有一句：把 TTS 的中间表示从梅尔频谱图换成离散 codec token，于是任务性质从「回归一张连续的二维图」变成「语言建模，猜下一个 token」。**

这一改，GPT 那套东西里最值钱的能力就被搬了过来，也就是 **in-context learning**：不用微调、不用改结构，在 prompt 里给例子，模型照着做。VALL-E 把一段 3 秒的陌生人录音当作前缀塞进去，模型就会照着那个人的嗓子接着说。

**表征直接用现成的 EnCodec**，没自己训 tokenizer。配置是 24 kHz、帧率 75 Hz、8 层 RVQ、每层码本 1024 条，对应 6 kbps。10 秒音频编码成一个 750 × 8 的矩阵。论文特意说明为什么选 codec 而不是 HuBERT code：HuBERT 把说话人身份丢掉了（这正是它作为语义表征的优点，但对克隆音色是致命的），而 codec token 富含说话人和声学信息，且自带解码器不用再训 vocoder。

**核心难题是这 8 层 token 怎么生成。** 全自回归的话 10 秒就是 6000 步，太慢；全并行又不知道该生成多长。VALL-E 的解法是拆成两个模型：

- **AR 模型只管第 1 层**。decoder-only 因果 Transformer，条件是音素序列 + 参考录音第 1 层的声学 token。用自回归是因为**不知道要生成多长**，论文说得很实在：不同说话人语速差异太大，很难训一个跨说话人的时长预测器。自回归让模型自己吐 `<EOS>` 决定长度。
- **NAR 模型管第 2 到第 8 层**。第 1 层生成完长度就定了，后面 7 层的槽位数量跟着走，于是可以并行，把时间复杂度**从 O(T) 降到 O(1)**。NAR 一共只调用 7 次，每次生成一整行。用 AdaLN 注入当前是第几层：`AdaLN(h,i) = aᵢ·LayerNorm(h) + bᵢ`。

这个 AR + NAR 的分工是全文最精巧的设计，也是留给后世最重要的遗产之一。

**两种 prompt 分工明确**：音素 prompt（参考录音的转录 + 待合成文本拼起来）管内容，声学 prompt（参考录音的 codec 矩阵）管音色。AR 只用声学 prompt 的第 1 层，NAR 把 8 层 embedding 求和全用上。一个很聪明的点是 **AR 训练时根本没有 prompt 这个概念**，就是纯粹的因果语言模型训练，任何前缀自动成为后面部分的 prompt，prompt 只在推理时才出现，这跟 GPT 完全一致。

**数据是这篇真正的赌注。** LibriLight 6 万小时英语有声书、约 7000 个说话人，而且是**无标注**的，用一个 Kaldi 训的 DNN-HMM ASR 模型打上音素级对齐（30ms 帧移）变成可用数据。此前 TTS 预训练工作用的数据都不到 1000 小时。论文自己下的判语是 **simple scaling up semi-supervised data has been underestimated for TTS**。

模型规模：AR 和 NAR 架构相同，12 层、16 个注意力头、embedding 1024、FFN 4096、dropout 0.1。16 张 V100 32GB，每卡 batch 6k acoustic token，训 80 万步，AdamW 前 32k 步 warmup 到 5e-4 后线性衰减。推理时 AR 用采样解码，NAR 用贪心。

## 结论

**LibriSpeech 零样本评测**（测试说话人在训练数据里一个都没出现过，基线是当时 SOTA 的 YourTTS）：

| 模型 | WER ↓ | 说话人相似度 ↑ |
|---|---|---|
| 真人录音 | 2.2 | 0.754 |
| GSLM（用 HuBERT code） | 12.4 | **0.126** |
| YourTTS | 7.7 | 0.337 |
| **VALL-E** | **5.9** | **0.580** |
| VALL-E-continual | 3.8 | 0.508 |

相似度 0.337 到 0.580 几乎翻倍，WER 还同时下降。GSLM 的 0.126 是最好的反面教材，印证了「HuBERT code 丢音色」这个表征判断。

**人工评测**。LibriSpeech 40 个说话人：SMOS 从 YourTTS 的 3.45 提到 4.38（真人 4.5），CMOS 领先基线 0.12。VCTK 60 个说话人：SMOS 3.81 对 3.70，CMOS 领先 0.23。**最惊人的一格是 VCTK 上真人录音的 CMOS 比 VALL-E 低 0.04**，也就是自然度上听众已经分不出合成和真人了。而且基线 YourTTS 在 VCTK 上见过 108 个说话人里的 97 个，VALL-E 一个都没见过。

**消融实验把两个 prompt 的分工拆得像教科书**（NAR，输入用真值第一层 token）：

| 配置 | WER ↓ | SPK ↑ |
|---|---|---|
| 都不给 | 19.6 | 0.518 |
| 只给音素 prompt | 3.0 | 0.541 |
| 音素 + 声学 prompt | 2.8 | 0.732 |

音素 prompt 把 WER 从 19.6 拉到 3.0 而相似度几乎不动，声学 prompt 把相似度从 0.541 拉到 0.732 而 WER 只微降。AR 那边更极端：去掉声学 prompt，**WER 完全不变（都是 5.9），相似度从 0.585 崩到 0.236**。两个变量被完美分离。

**涌现能力**：模型会连带复制参考录音的**声学环境**（比如混响）和**情绪**（比如愤怒），这些都没有被显式训练过。另外因为 AR 用采样解码，同一段文本同一个说话人可以生成多样的结果。

## 局限

- **论文自己承认合成结果有时吐字不清、丢词、重复**，原因是音素到声学的映射是自回归的、对齐是隐式的，**没有任何显式对齐约束**。这个毛病后来催生了一整条研究线。
- **AR 阶段不能用 beam search**，论文明说会让语言模型陷入无限循环，只能用采样。这既带来了输出多样性，也暴露了模型本身不够稳。后来 TTS 的鲁棒性问题根子就在这里。
- **数据覆盖太窄**，LibriLight 全是英语有声书朗读，口音、带情绪的说话方式、非朗读风格严重不足。论文自己也提了。
- **序列太长**。75 Hz × 8 层 = 每秒 600 个 token，10 秒音频 6000 个 token。后来整个领域往 12.5 Hz 低帧率跑，就是在解这个问题。
- **EnCodec 是拿来主义**。它为「压缩传输」而训，不是为「被语言模型建模」而训，这个错配正是 MOSS-Audio-Tokenizer 那篇要解决的事。
- **没有开源**，微软只放了 demo 页，能跑的都是社区复现（如 VALL-E-X）。这让复现和对比研究都很困难。
- **伦理风险只用一段话带过**。3 秒克隆任意人声，滥用门槛极低，论文说「可以建检测模型」但没做。

## 对我意味着什么

- **这是 codec-LM 路线的起点，后面所有 TTS 论文都在跟它对话。** 三元组填法：表征 = EnCodec 的离散 token，生成器 = AR + NAR 双 Transformer，条件 = 音素 prompt + 声学 prompt。
- **最该抄的范式转变：把「音色」从一个需要专门模块（speaker encoder）解决的问题，变成一段放在上下文里的前缀 token。** 这跟 Fan 2026 那篇「音色应该是一次性指定的全局条件」是同一件事的两种实现，都在说不要让模型每步去维持一个属性。
- **AR + NAR 的分工思路后来进化成 Temporal Transformer + Depth Transformer**（MOSS 那篇）。判据是一样的：**长度不确定的维度必须自回归，长度已定的维度可以并行**。这条在读后面任何多流生成模型时都能直接套用。
- **它暴露的两个问题定义了后续三年的议程**：一是隐式对齐导致的鲁棒性差，二是序列太长。前者通往 MaskGCT 那类不需要显式对齐又稳定的方案，后者通往低帧率 tokenizer。读后面的论文时可以直接问：这篇在解 VALL-E 留下的哪个坑。
- **数据规模被低估这条判断值得记住。** 6 万小时对不到 1000 小时，架构上并没有多神奇，赢在数据量级。这和 MOSS 那篇「端到端加规模打败精巧设计」是同一个剧本。
