# Dai 2026

**定位**：LM 规划 + 流匹配渲染的现代解剖图

#### Hierarchical AR Planning + Flow-Matching Rendering

**引用:** Dai et al.(Alibaba "Token Foundry",16 人等贡献),*Pushing the Frontier of Full-Song
Generation: Hierarchical Autoregressive Planning Meets Flow-Matching Rendering*,arXiv 2607.20253(2026-07)。
**生成侧论文,不是检测侧** —— 收它是因为它把"AI 生成路径"的现代解剖图公开了。

#### TL;DR
阿里的商业级全曲生成系统技术报告:歌词/文本 → 完整歌曲(最长 5 分钟,48kHz 立体声)。
Artificial Analysis 人声音乐榜 **Elo 1129、排 2–3**,对标 Suno V5.5 / Mureka V8 / Lyria 3 Pro。
**闭源**(无代码无权重,仅 demo 页)。

#### 管线(现代生成器长这样)
1. **语义感知 RVQ tokenizer**:音频 → 8-codebook RVQ 离散 token(BEST-RQ 预训 → 多任务微调 → RVQ 训练);
2. **Hybrid-LM 分层自回归规划**:8B 全局 LLM 每帧预测第 1 个 codebook,0.4B 局部 LLM 自回归补残差
   codebook —— 按歌词/文本规划出离散音乐 token;
3. **FullDiT 流匹配渲染**:8B DiT 在**连续 VAE latent 空间**做全曲 flow matching(条件 = codec token +
   歌词 + 文本),补足声学细节;最长 8192 帧 @ 25Hz = 327.68 秒;
4. **两级旋律模块**(翻唱用):note 级 + frame 级音高线索 → 粗/细粒度旋律 token。

评测:SongBench / SongEval / AudioBox-Aesthetic / CMI-Reward + Artificial Analysis 榜(2,105 样本)。

#### 对我们的意义
- **"AR 规划 + 流匹配渲染"= 当前主流配方**(它、ACE-Step、DiffRhythm 2 都是)
  → 我们 cross-generator 选 ACE-Step,恰好覆盖这个最重要的架构族
- **对重建法的警示具体化**:现代生成器的最终渲染是**流匹配 DiT,不是 EnCodec 类卷积声码器**
- 佐证 流匹配相关实验及想法 这条线的时代性:检测想跟上生成,得理解流匹配路径;
- **不能当测试生成器**(闭源);弹药仍是 [[FakeMusicCaps]] + ACE-Step。
