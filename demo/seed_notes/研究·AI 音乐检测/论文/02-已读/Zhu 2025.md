# Zhu 2025

**定位**：MuQ(Mel-RVQ)出处,round-1 最强编码器

#### Self-Supervised Music Representation Learning with Mel-RVQ

**引用:** Haina Zhu, Yizhi Zhou, Hangting Chen, Jianwei Yu, Ziyang Ma, Rongzhi Gu, Yi Luo,
Wei Tan, Xie Chen(Tencent AI Lab / SJTU).arXiv:2501.01108 (2025),另见 IEEE TASLP。
代码/权重:github.com/tencent-ailab/MuQ。**这就是我们 round-1 最强编码器(EER 0.00%)的出处**, [[MuQ]]

#### TL;DR
音乐自监督(SSL)模型。老办法(如 MERT)用 **EnCodec** 或 **BEST-RQ 随机投影**当"预测目标",
一个算力重、一个依赖随机初始化不稳。MuQ 提出 **Mel-RVQ**:直接对 **mel 频谱**做残差向量量化当目标,
**又快又稳**(单 GPU 预训 <1 小时)。结果在 MARBLE 基准上**全面超过 MERT**,是当前音乐 SSL 的 SOTA 之一。

#### 核心贡献:Mel-RVQ(怎么造"预测目标")
- SSL 的套路:把音频某种"离散 token"当标准答案,让模型去预测。**关键就在这个 token 怎么来**。
- **Mel-RVQ = 直接量化 mel 频谱**:用**单层线性 encoder/decoder**(而非 EnCodec 的卷积)做残差向量量化,
  **N=8 个 codebook,每个大小 K=1024**;损失 = codebook + commitment + 重建三项。
- **为什么更好**:
  - 比 MERT 用的 **EnCodec**:不用跑一整个卷积 codec → **算力轻**;
  - 比 **BEST-RQ**(随机投影):**不依赖随机初始化** → 目标更稳定、可复现;
  - Mel-RVQ 本身预训 **<1 小时 / 单卡**。

#### 架构 & 训练
- **主干:12 层 Conformer,310M 参数**;输入 **128 维 mel、25Hz 时间分辨率、30s @ 24kHz**。
- **数据**:先 **0.9K 小时**开源(Music4All)就已超过既往模型;再扩到 **160K 小时**自有数据。
- **迭代训练(iter)**:用第 **10 层**的隐表示重训 Mel-RVQ(Mel-RVQ_iter),再多训 150K 步 → **MuQ_iter**,进一步涨点。
- 注意:我们用的开源权重 `MuQ-large-msd-iter` = 在 **Million Song Dataset** 上的 **iterative** 版本
  (论文最好成绩用的是 160K 小时自有数据;开源 checkpoint 用 MSD)。

#### 结果(MARBLE 基准,9 项任务平均)
| 模型 | 平均分 |
| --- | --- |
| **MuQ_iter** | **77.0** |
| **MuQ**(160K) | 76.7 |
| MusicFM | 75.4 |
| MERT | 74.4 |
- 分项优势:genre 85.5(vs 83.8)、singer-ID 95.8(vs 92.0)、instrument 79.2(vs 76.2)。
- MARBLE 9 项:genre / key / emotion / singer-ID / vocal-technique / tagging / structure / instrument / pitch。

#### 对我们项目的意义
- **解释了"为什么 MuQ 在 round-1 直接 0.00% EER"**:它本就是最强的音乐表示之一,
  在我们**带混淆**的数据上几乎任何东西都能线性可分 → **正因为太强,反而没法用它在混淆数据上做选型**。
- 结论:MuQ 是很强的**前端候选**,但**去混淆之前不下选型结论**。
