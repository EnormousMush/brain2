# Zhang 2024b

**TCSinger: Zero-Shot Singing Voice Synthesis with Style Transfer and Multi-Level Style Control** · Yu Zhang, Ziyue Jiang, Ruiqi Li 等（浙江大学 + 上海人工智能实验室，Zhou Zhao 通讯，与 GTSinger、Prompt-Singer 同组）· EMNLP 2024 · https://arxiv.org/abs/2409.15977 · https://github.com/AaronZ345/TCSinger · https://aaronz345.github.io/TCSingerDemo/

## 它做了什么

第一个把 GTSinger 那套音素级技巧标注真正吃进模型的工作，同时做两件事：零样本风格迁移（给一段未见歌手的音频，把音色和风格搬到新歌词新乐谱上）和多层级风格控制（用文本指定全局的唱法、情绪，和每个音素的技巧）。这里的风格指五类：唱法、情绪、节奏、技巧、咬字。

对比 Prompt-Singer 的三个属性、整首歌粒度、分类级控制，这篇的进步在粒度：控制细到音素。模型收到的音素级提示形如 `[ [vibrato], [falsetto], [], [breathy, vibrato], ... ]`，一句歌词 N 个音素就给 N 个列表，每个列表零个、一个或多个技巧。这个能力直接由 GTSinger 的音素级标注解锁。

**整体是两阶段的：先学表示和解码器，再学这个表示上的先验。** 阶段一训 clustering style encoder 做重建，阶段二训 S&D-LM 做风格预测。这和 VQ-VAE 加 PixelCNN、以及隐扩散先训 VAE 再训扩散是同一个模式，见 [[latent]]。主 SVS 模型训 300k 步，S&D-LM 训 100k 步，4 张 3090Ti。

**三种表示的分工。** 内容来自 phoneme encoder 和 note encoder；风格来自 clustering style encoder，是音素级的序列；音色来自 timbre encoder，是**一个一维向量**。分工的依据是时间尺度：音色在整段里不变，压成一个向量即可；风格逐音素变化，必须是序列。timbre encoder 吃的 prompt mel 是从**同一歌手的另一段音频**里采的，这样它学不到当前内容，只能学音色，等于从构造上消除混淆。

**组件一，clustering style encoder。** 流程是 mel 过 WaveNet blocks，按音素边界 pooling 成音素级，过卷积堆捕捉音素级相关性，线性投影降到低维，再过 CVQ 层输出音素级风格表示。三个设计点：按音素边界 pooling 决定了后面一切的粒度都是音素级，这是音素级控制的前提；线性投影降维是为了提高码本使用率（引自图像域 ViT-VQGAN），维度太高时编码器输出散得太开，大部分码向量永远选不上；CVQ 取代普通 VQ 是为了解决 codebook collapse，即 512 个码向量里只有少数被反复使用、其余从初始化后再没被选中因而梯度永远传不到，CVQ 的做法是动态初始化，让用得少或没用过的码向量被修改得比常用的更多。另外对编码输出和全部码向量都做 ℓ2 归一化。码本大小 512。论文说这是第一次把 CVQ 用在歌声领域。

论文明确写道，线性投影降维加上 CVQ 的量化共同构成一个 information bottleneck，把非风格信息挤出去，实现风格与音色、内容的解耦。见 [[information-bottleneck]]。

**组件二，S&D-LM（Style and Duration Language Model）。** 两个设计选择都给了非套路的理由。用语言模型预测风格，是因为风格既有局部依赖也有长程依赖、随时间快速变化、且与内容相关性弱，这三条正好是条件语言模型擅长的场景，而风格经 CVQ 之后正好是离散符号。把音素时长和风格一起预测，是因为歌声的音素时长变化极丰富且与风格紧密相关，两者互为线索。结构是 decoder-only transformer，8 层，512 维，教师强制训练。

迁移模式下输入拼接 prompt 时长 d、prompt 风格 s、prompt 内容 c、目标内容 c̃、目标音色 t̃，自回归预测目标风格 s̃ 和目标时长 d̃。这是标准的 in-context learning 格式，零样本能力就来自这里：模型没见过这个歌手，但见过大量「prompt 风格到目标风格」的配对，学到的是这个映射本身。控制模式下不再从音频抽 s 和 d，改用 text encoder 编码全局与音素级文本提示 tp，与 c、c̃、t̃ 拼接。训练时用一个概率 p 决定这一批训迁移还是训控制，所以一套模型同时会两件事。

**组件三，style adaptive decoder。** 动机是对组件一的诚实补救：VQ 本身有损，相近的风格容易被编成同一个码本索引，此时若用普通 mel 解码器，生成结果会僵硬、缺少风格变化。解法是让风格在解码的每一层再注入一次，方法叫 mel-style adaptive normalization：

m_i = φ_γ(s) · ( m_{i-1} − μ(m_{i-1}) ) / σ(m_{i-1}) + φ_β(s)

先用 LayerNorm 把上一层的 mel 谱归一化成均值 0 方差 1，再用从风格向量 s 算出的缩放和偏移重新调制。关键在于风格不是被加进去的，而是决定了这一层的 γ 和 β，所以哪怕两个相近风格拿到同一个码本索引，只要 s 有细微差别生成结果就不同。解码器本体是 8 步扩散解码器，去噪器用 FFT 块，损失是 MAE 加 SSIM。这套手法在图像领域叫 AdaIN，论文声称自己是第一个用解耦出的风格信息去 refine 整张 mel 谱的。见 [[normalization]]。

**F0 由 pitch diffusion predictor 生成**，条件是 s̃、d̃、t̃、c̃，损失是高斯扩散损失加多项式扩散损失，沿用 RMSSinger 的做法。注意这篇**不对 F0 做显式分解**，与 Prompt-Singer 拆成音域加旋律的路线正好相反，见 [[pitch-representation]]。

**五个损失**：CVQ 损失、音高的高斯与多项式扩散损失、mel 的 MAE 与 SSIM、时长的 MSE（对数尺度）、风格的交叉熵。后两个在教师强制模式下算。

**数据。** GTSinger 中英子集只有 5 歌手 36 小时，不够训零样本，所以另加 M4Singer（20 歌手 30 小时中文歌声）、OpenSinger（93 歌手 85 小时中文歌声）、AISHELL-3（218 歌手 85 小时中文语音）、PopBuTFy 子集（20 歌手 18 小时中英语音与歌声），**并由作者自己手工标注全局风格标签和六种音素级技巧**。40 个歌手留作未见测试集。采样率 48 kHz，窗长 1024，hop 256，80 个 mel bin，声码器为预训练 HiFi-GAN。

## 结论

四个任务全部零样本。

零样本风格迁移（Table 1）：TCSinger 的 MOS-Q 4.12、MOS-S 4.28、FFE 0.22、MCD 3.16、Cos 0.92，全面优于最强基线 StyleSinger 的 3.94 / 4.01 / 0.28 / 3.23 / 0.89，以及 RMSSinger 3.86 / 3.80 / 0.29 / 3.29 / 0.83、Mega-TTS 3.81 / 3.87 / 0.29 / 3.45 / 0.84、YourTTS 3.67 / 3.76 / 0.35 / 3.55 / 0.82。GT 过声码器是 4.34 / 4.39 / 0.05 / 1.33 / 0.96，真人 MOS-Q 4.58。

多层级风格控制（Table 2）：这个任务是本文自己开的，其他基线都是被加上全局与音素级文本 embedding 之后才能参赛。parallel 设定下 TCSinger 的 MOS-Q 4.05、MOS-C 4.18、FFE 0.24、MCD 3.20，non-parallel 下 3.95 / 4.09，均优于 StyleSinger 的 3.89 / 3.93 / 0.29 / 3.45 和 3.79 / 3.85。

跨语言风格迁移（Table 3）：TCSinger 3.98 / 4.11，StyleSinger 3.85 / 3.80。语音转歌声（Table 4，平行）：TCSinger 3.94 / 4.05 / FFE 0.24 / Cos 0.90，StyleSinger 3.80 / 3.78 / 0.30 / 0.86。

消融（Table 5，用 CMOS-Q 和 CMOS-S，以完整模型为 0 点）：

| 设定 | CMOS-Q | CMOS-S |
|---|---|---|
| w/o CVQ（换回普通 VQ） | -0.25 | -0.23 |
| w/o 风格自适应解码器 | -0.22 | -0.18 |
| w/o 时长模型 | -0.12 | -0.22 |

前两项音质掉得比相似度多，符合它们管生成质量的定位。第三项反过来：把时长从 S&D-LM 里拿掉、改用简单时长预测器，音质只掉 0.12，相似度却掉 0.22，对像不像这个歌手的伤害是对音质的近两倍。这说明节奏是身份的一部分，一个人怎么处理字的长短、什么时候拖什么时候赶，和音色一样是他的签名。这个结论不在论文的强调里，但它是这张表最有信息量的地方。

## 局限

- 作者承认：只支持六种技巧，未覆盖全部常用技巧；跨语言只做了中英两种。
- **218 小时的自制标注没有任何质量报告。** GTSinger 中英子集只占训练数据的 14%，其余 86% 的风格标签由作者自行标注，而论文对标注者背景、标注规范、一致性、抽检机制只字未提。整个模型的风格能力建立在这批标注上。对比 GTSinger 论文里详细的 MFA 加 Praat 流程和 25% 专家复核，落差明显。
- 消融只报 CMOS，没有客观指标。CMOS 是以完整模型为 0 点的相对分，只能看出差多少，看不出绝对水位；同一张表里若有 FFE 和 MCD 会有说服力得多。
- 基线被改造过。YourTTS 和 Mega-TTS 是语音模型，加了 note encoder 才能处理乐谱；多层级控制表里所有基线都是被加上文本 embedding 才能参赛的。比的是这些模型接上外挂之后的表现。
- MOS-S 把音色相似度和风格相似度混在一个数里（论文自己的定义是 in terms of timbre and styles）。而这两件事恰恰是本文要解耦的对象，评测时又合起来打一个分，无法判断提升来自哪一边。
- 风格 token 的可解释性为零。论文声称建模了唱法、情绪、节奏、技巧、咬字五类，但 CVQ 输出的只是一串码本索引，哪些索引对应哪类风格没有任何分析，五类都建模了这个说法无法验证。
- 没有与 GTSinger 论文的数字直接对齐。StyleSinger 在 GTSinger 的 benchmark 上 MOS-Q 是 3.95，这里是 3.94，看着接近，但数据划分和测试集完全不同，两个数不可比。所以超越 SOTA 是在作者自己的划分上成立。
- 风格控制模式下 S&D-LM 的输入仍保留 prompt 内容 c，但已不需要 prompt 风格和时长。为什么还要留 c，论文没有解释，推测是为了与迁移模式共用同一套输入槽位。

## 对我意味着什么

- **控制粒度是一条独立的维度，而且由标注粒度决定，不由模型决定。** 全局到音素级是一次实质跃迁，前提是训练数据里每个音素都标了技巧。这是 GTSinger 那条「标注粒度决定控制粒度」的直接验证，也是先读 GTSinger 的价值所在。
- **information bottleneck 第三次出现。** NS2 的 32 个 query token、Prompt-Singer 的标量 f̄₀、这篇的 512 格码本加一维音色向量，三种实现同一个思路。已经够格当设计原则用。
- **解耦之后要在解码的每一层重新注入。** 这是这篇给的新东西。光在输入端给一次条件不够，因为量化有损；AdaIN 式的逐层调制是补救。往后看到任何 XX-adaptive normalization 都是同一个套路。
- **风格 token 是整个系统的枢纽，这解释了为什么一套模型能做两件事。** 迁移模式下 s̃ 从音频里抄，控制模式下 s̃ 从文字里生成，而下游的 pitch predictor 和 decoder 完全不知道 s̃ 从哪来。想让一个系统支持多种控制接口，就把它们收敛到同一个中间表示上，这个思路可以直接迁移。
- **节奏是身份的一部分。** 消融里 CMOS-S 掉 0.22 而 CMOS-Q 只掉 0.12。时长预测不只是工程细节，它承载音色之外的个人特征。这条在做音色克隆或歌声转换时值得记住。
- **同组三连读法。** GTSinger 造数据，TCSinger 吃数据，后面 TechSinger、TCSinger2 继续推进。浙大赵洲组是 SVS 这条线上最密集的产出方，当一条独立主线读比按时间顺序读清楚得多。
- **不拆 F0 也是一种选择。** Prompt-Singer 把 F0 显式拆成音域加旋律，这篇直接用扩散预测器生成、条件于风格和时长。两条路线并存，说明音高表示这个问题确实还没收敛。
