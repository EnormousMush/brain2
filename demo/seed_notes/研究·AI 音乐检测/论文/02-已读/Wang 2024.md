# Wang 2024

**Prompt-Singer: Controllable Singing-Voice-Synthesis with Natural Language Prompt** · Yongqi Wang, Ruofan Hu（共同一作）, Rongjie Huang 等（浙江大学，Zhou Zhao 组，与 GTSinger 同组）· NAACL 2024 · https://arxiv.org/abs/2403.11780 · http://prompt-singer.github.io

## 它做了什么

第一个用自然语言 prompt 控制歌声属性的 SVS 模型，可控的三个属性是歌手性别、音域、音量。

之前控制歌声风格只有两条路：用固定的歌手 ID（只能选训练时见过的），或者给一段参考音频（NS2、Make-A-Voice 走这条）。前者不能泛化，后者要求你先有目标音频。自然语言的好处是不需要素材，张嘴就能用，对非专业用户友好。

论文列了三个拦路虎：音域和旋律耦合、没有为歌声风格描述定制的文本表示、歌声数据稀缺。

**核心贡献：解耦的音高表示。**

难点在于音域和旋律都活在 F0 里，数据集中每条音高标注都绑在某个歌手的某个音域上，两者从未分开过。依据是等程律：人对音程的感知对应频率的对数距离，所以整条 F0 乘以同一个因子等价于在对数域整体平移，音域改变而旋律形状不变。

据此把 F0 拆成两份：

- f̄₀ 是浊音部分 F0 的算术平均值，**一个标量**，代表音域。
- f̃₀ 是把 F0 重缩放到均值等于 230 Hz 之后的序列，**一条序列**，代表与音域无关的旋律。

因为是构造出来的，所有样本的 f̃₀ 均值都恒等于 230，音域这个维度被物理抹平，f̃₀ 里只剩帧与帧之间的比值，而音程就是频率比，所以旋律信息完整保留。举例：F0 = [262, 294, 330, 294, 262] 时 f̄₀ = 288.4，f̃₀ = [208.9, 234.5, 263.2, 234.5, 208.9]，330/262 = 1.2595 与 263.2/208.9 = 1.2599 一致。

两者都四舍五入成整数，用同一张 LUT 嵌入，共享 embedding 空间。取整之后 F0 的取值空间变成有限整数集合，等价于一个以赫兹数为词的词表，查表就是普通的 embedding lookup。

论文明确指出这是一个 information bottleneck：音域被压成一个数，模型没有别的通道能拿到音域，也没有别的通道能拿到旋律，通道被物理隔开。

**序列结构：f̄₀ 是中间输出，不是输入。**

训练时把条件输入和目标输出拼成一整条序列喂给 decoder-only transformer，next-token-prediction，交叉熵只在目标段上算。前缀是 prompt 向量、帧级音素序列、f̃₀ 序列，目标段是 f̄₀ 后接声学 units。推理时模型先预测 f̄₀，再把预测出的 f̄₀ 当条件继续自回归生成声学 units。

论文假设 f̄₀ 独立于歌词、时长、旋律，因此条件里唯一能影响 f̄₀ 的只有 prompt，这是 prompt 能控音域在数学上成立的地方。对比不做解耦的情况：音域弥散在整条 F0 里，模型必须连续几百帧都恰好选中偏高或偏低的 token 才不漂移；解耦之后只需在一个位置上决定一个数。

**多尺度 transformer。**

主干取自 UniAudio 的 multi-scale transformer，由 global 和 local 两个 decoder-only transformer 组成。对时间位置 t，把 C 个码本的 embedding 拼接后喂 global transformer 建模帧间相关性，输出 h_t 自回归地条件于 h_1 到 h_{t-1}；h_t 按原形状切分、线性投影后加到 local transformer 的输入 embedding 上作为帧级上下文，local transformer 在一帧内部自回归预测 C 个码本的 token。非声学模态的每一项要重复 n_q 次以对齐这个机制，n_q 为码本数。

配置：global 20 层 320M 参数，local 6 层 100M，hidden 维度都是 1152。声学 units 来自自训的 SoundStream，24 kHz，12 层量化，码本 1024，降采样率 480，只用前 3 层，因此帧率 50 Hz、token 率 150 TPS。最后不用 codec 解码器，单独训了一个 BigVGAN 血统的 unit vocoder，因为 3 层码本经 codec decoder 重建音质不足。

**prompt 数据是造出来的。**

没有现成数据集，用 GPT-3.5 Turbo 生成。三步：属性分类（性别用数据集自带标签；音量按振幅 RMS 分低 [0.02, 0.04]、中 [0.07, 0.10]、高 [0.16, 0.20] 三档，训练时可动态重缩放；音域按浊音部分平均 F0 分两档，男声阈值 125 Hz、女声 305 Hz）；生成关键词和句式模板（每类 4 到 7 个同义词，每个属性约 50 个模板，人工筛选）；训练时现场拼装（以概率 p1、p2 各 0.05 随机丢弃一到两个标签，再随机取关键词和模板）。音域不单独控制，必须与性别同时给出，因为男女的音域分界不同。

**数据稀缺的应对是混入 TTS 数据。** 出发点是说话和唱歌都是人声，风格特征上有共通。把 TTS 数据按同样方式音素化、造 prompt、抽 F0，做成与 SVS 数据相同的格式混合训练。歌声 127 小时（M4Singer、Opencpop、Opensinger、PopCS），语音 179 小时（AISHELL-3、标贝、THCHS-30、DidiSpeech 子集），全部为普通话。

## 结论

因为是全新任务没有前作可比，实验全是框架内部的对照。

文本编码器对比（Table 1，共 10 个配置）。微调带来明显收益：FLAN-T5 large 从预训练到微调，性别准确率 83.1/80.8 升到 87.7/86.3，音量 92.7 升到 94.4，音域 82.6 升到 84.7。论文解释是把文本表示对齐到分布简单得多的标签空间，更容易学到描述与风格的对应。模型规模有收益但会饱和：small 到 base 到 large 提升明显，large 到 XL 几乎不动，说明文本编码器不是瓶颈。不同编码器擅长的属性不同：FLAN-T5 系控音量比 CLAP 和 BERT 弱 1.2 到 2.3 个点，但控音域强 1.8 到 4.0 个点，论文归因于预训练方法与数据的差异，未深究。最终选 FLAN-T5 large 微调版。

横向看，可控模型的 R-FFE 最好 0.09、MOS 最好 3.90，与不可控的 DiffSinger（0.09 / 3.86）基本持平，说明加入可控性没有牺牲音质。真人 MOS 为 4.09，性别准确率 98.0/97.0。

**解耦的消融（Table 3）是全篇最有信息量的一张表。**

| 配置 | 性别 F/M | 音量 | 音域 | R-FFE↓ | RMOS |
|---|---|---|---|---|---|
| 因子 + 重缩放 | 87.7 / 86.3 | 94.4 | 84.7 | 0.12 | 3.62 |
| 去掉因子 | 78.1 / 63.0 | 91.3 | 76.1 | 0.11 | 3.34 |
| 再去掉重缩放 | 64.4 / 58.9 | 91.6 | 72.3 | 0.08 | 2.75 |

去掉音域因子，性别掉 9.6 / 23.3、音域掉 8.6、RMOS 掉 0.28；再去掉输入 F0 的重缩放，性别再掉 13.7 / 4.1、音域再掉 3.8、RMOS 再掉 0.59。但 R-FFE 反向变好，0.12 到 0.11 到 0.08。作者承认解耦机制会损失一部分音高信息。**可控性和保真度之间存在实质取舍**，这是本文最值得带走的结论。

数据稀缺（Table 2）。全量对照下混入语音数据使所有指标全面提升（性别 75.3/65.8 到 87.7/86.3，音量 87.6 到 94.4，音域 78.7 到 84.7，MOS 3.68 到 3.89），代价仅是 R-FFE 涨 0.01，作者解释为歌声旋律与说话韵律的分布差异都体现在音高变化上，会轻微干扰旋律建模。

低资源实验（固定 100 小时语音，歌声从 100 小时减到 10 分钟）的结论更有价值：音域几乎不掉（82.3 到 80.9），音量掉得慢（92.5 到 78.3），而性别（86.2/80.5 到 65.8/65.6）、R-FFE（0.12 到 0.29）、MOS（3.75 到 3.06）全线崩塌。即语音数据能替代的是说话中同样存在的属性，替代不了歌声特有的部分。

多属性（Table 3 后半）：prompt 里提 1 个、2 个、3 个属性，性别从 87.7/86.3 降到 84.3/82.9 再到 81.2/80.7，RMOS 从 3.67 降到 3.52，下降平缓。

## 局限

- 作者承认：prompt 由模板拼装，存在分布偏差，表现为语法错误、表达不自然、多样性受限。建议的解法是再过一遍 LLM 润色，但没有实施。
- 作者承认：文本编码器加自回归生成导致推理延迟可观。
- 只控制三个属性（性别、音域、音量），且都是分类级而非连续调节，音域仅两档、音量三档。对比 GTSinger 提供的六种技巧加四类风格标签，可控维度相差很远。情绪、节奏、演唱技巧全部缺席，作者把这些列为 future work。
- 全部数据为普通话，跨语言能力完全未验证。
- 性别准确率依赖一个自训的分类器，而该分类器本身的性能未单独报告。音量和音域的评测是直接量 RMS 和平均 F0，客观性没有问题。
- 取整这一步本身是有损量化（我的推断，非论文所述）。1 Hz 在 100 Hz 处约 17 音分、在 230 Hz 处约 7.5 音分，而颤音幅度约 ±50 音分，因此取整会吃掉音高细节的一小部分，很可能是 R-FFE 退化的来源之一。

## 对我意味着什么

- **音高该怎么表示，是 SVS 里没有定论的开放问题。** 同一个对象 F0 上存在多种正交的拆法：GTSinger 拆成真实乐谱加 F0 曲线，本文拆成音域标量加归一化旋律序列。往后每读一篇 SVS 或 SVC，固定问一句：它把 F0 拆成了什么，为什么这么拆。
- **可控性和保真度之间存在实质取舍，而且被量化了。** Table 3 里解耦让控制准确率涨 20 个点以上，同时让 R-FFE 从 0.08 退到 0.12。这个矛盾会在后续论文里反复出现，是个好的追踪指标。
- **information bottleneck 是让属性可控的通用手法。** NS2 把说话人信息压成 m = 32 个 query token，本文把音域压成一个标量。手法一致：给要控制的属性一条又窄又专的通道。这条接 [[latent]] 里的表示设计，也接 Fan 2026 那条「凡是需要全程维持的属性都该变成一次性指定的全局条件」。
- **一帧多码本的建模有两种主流拆法**，VALL-E 的 AR 加 NAR 两段式，和本文的 global 加 local 两级 transformer。后面每篇 codec-LM 基本都在这两者之间选，或者走全非自回归（MaskGCT）。这是个好用的分类维度。
- **歌声数据不足就借语音数据，是这个领域的一条明线。** NS2 用说话 prompt 合成歌声，本文直接混入 TTS 数据，而且量化了能借到什么、借不到什么。这个结论可以直接用在别处：说话里同样存在的属性可以借，歌声特有的不能借。
- 本文与 GTSinger 同组同一批人，可以把浙大赵洲组当成一条独立的线来读，后面 TCSinger、TechSinger、TCSinger2 大概率是同一批人的延续。
