# Guo 2025

**TechSinger: Technique Controllable Multilingual Singing Voice Synthesis via Flow Matching** · Wenxiang Guo, Yu Zhang, Changhao Pan 等（浙江大学，Zhou Zhao 通讯，与 GTSinger、Prompt-Singer、TCSinger 同组）· AAAI 2025 · https://arxiv.org/abs/2502.12572 · https://github.com/gwx314/TechSinger · https://gwx314.github.io/tech-singer/

## 它做了什么

支持五种语言、七种技巧的可控歌声合成。技巧从 GTSinger 的六种扩到七种，新增气泡音（bubble，也叫 vocal fry）和强度（intensity），其中气泡音正好是 GTSinger 自己在局限里写「没覆盖」的那一个。

它同时是**第一个把 flow matching 用进 SVS 的工作**，而且用了两次。

### 先补三个词

**帧**：声音是连续的，电脑处理不了，所以切成一小段一小段，每段几毫秒到几十毫秒，一秒几十到上百帧。帧是声音世界的像素。

**F0（基频）**：你唱的是哪个音。声音里最低的振动频率，人耳听成音高。一段歌的 F0 连起来是一条上下起伏的曲线，这条曲线就是旋律的骨架。颤音是这条线在小幅抖动，滑音是这条线在爬坡，气泡音是这条线在结巴。

**梅尔谱**：声音的一张照片，横轴时间、纵轴频率、颜色深浅表示能量。像声音的 X 光片。直接生成波形太难（一秒几万个数），所以先画这张图，再用声码器（这篇用 HiFi-GAN）把图变回声音。这是整个语音和歌声领域的标准做法。

### 整条流水线

一条主线加两个外挂：

主线是六个工位。读稿（歌词拆成音、乐谱拆成音高和时值），排时间（每个字唱多久），画 F0 曲线（flow matching 第一次），起草粗糙的梅尔谱，精修梅尔谱（flow matching 第二次），最后 HiFi-GAN 出声。

外挂一是**技巧检测器**：听音频，说出每个字用了什么技巧。解决训练数据从哪来。
外挂二是**技巧预测器**：一句人话，输出每个字该用什么技巧。解决用户怎么用。

两个外挂都不参与合成，但缺了这套东西立不住。

### 为什么不能直接预测 F0

这是理解全篇的钥匙。

最朴素的做法是让模型直接吐出一条 F0 曲线，跟真值比，差多少罚多少。问题在于**同一份输入的正确答案不止一个**：同一句歌词、同一个乐谱、同样标着用颤音，一百个歌手会唱出一百条不同的曲线，抖的快慢深浅、什么时候开始抖都不同，而它们全都对。

「罚差多少」这种训练方式会把模型推向所有正确答案的平均值，因为站在正中间总罚分最小。一百条抖法不同的曲线平均起来，抖动互相抵消，结果是一条平的直线。类比是让一百个人画同一棵树再把画叠起来取平均，得到的不是树，是一团灰雾。

**这就是 Table 1 里其他模型 F0 曲线偏平的真正原因**，不是模型笨，是训练方式决定了它只能给平均答案。所以需要一种能给出具体而多样的答案的方法。

### flow matching 是什么

比喻是把一团随便撒的沙子搬成一个雕像的形状。起点是一堆随机数（乱撒的沙），终点是一条真实的 F0 曲线（雕好的形状），要学的是怎么搬过去。

做法是给空间里每个位置规定一个方向和速度，让沙子自己走过去。这套规则叫**速度场**，可以想成一阵设计好的风，风一吹沙子自动聚成形状。

**这阵风怎么学出来**，是最妙的地方，而且朴素得出乎意料。训练时起点和终点你都知道（噪声是自己撒的，真值是数据里的），那就在两点之间画一条直线，然后问：从起点沿直线走到终点，路上任意一个位置该往哪走、走多快。答案显而易见，方向就是终点减起点，速度全程恒定，因为直线上速度不变。

于是训练变成一件很傻的事：随机挑一个中间位置（走了三分之一、走了一半），让模型看着这个位置猜该往哪走，跟正确答案对一下，猜错就调。反复几十万次，模型就学会了站在任何位置都知道往哪走。这就是 `L = ‖v(x_t, t) − (x₁ − x₀)‖²` 的全部含义。

用的时候随手撒一把新沙子，问模型现在该往哪走，走一小步，再问再走，几十步之后就落在一个真实曲线的形状上。

**为什么这样就不平均了：因为起点是随机的。** 换一把沙子就落到另一个具体的形状上。模型学的不再是那一个平均答案，而是整片合法答案所在的地形。

这篇用的是 rectified flow matching，也就是**直线**路径，`x_t = (1−t)x₀ + t·x₁`，和我 [[flow-matching]] 笔记里写的一模一样。Voicebox 用的是最优传输路径，直线的好处是路径最短、采样步数可以更少。

### 用了两次

第一次是 FMPP（Flow Matching Pitch Predictor），终点是 RMVPE 抽出来的真实 F0，条件是乐谱和技巧序列。

第二次是 CFGFMP，精修梅尔谱。这里是两步走：先用朴素方法（罚差多少）画一张粗糙的梅尔图，因为是平均答案所以糊、缺细节；再用 flow matching 走一遍，把粗图当参考生成精细的图。类比是先用铅笔起稿保证结构不跑偏，再上颜料保证质感。论文原话是粗解码器「假设了单峰分布」，人话就是假设正确答案只有一个，所以结果「缺乏自然度和多样性」。

### CFG 让指定的技巧真的做出来

问题是你说这个字用颤音，模型可能只意思意思抖一下，听不出来。

第一步，**训练时故意失忆**：有 10% 的时候不告诉模型该用什么技巧，让它蒙着眼睛唱。这样同一个模型练出两种本事，知道技巧时怎么唱，和不知道技巧时怎么唱（平均的、没特色的唱法）。

第二步，**用的时候做减法**。想象两阵风，风 A 是知道要颤音时该怎么吹，风 B 是什么都不知道时该怎么吹。A 减 B 剩下的就是颤音这件事本身造成的差异。那就可以把差异放大：

最终的风 = 风 B + γ × (风 A − 风 B)

γ=1 就是风 A（正常），γ=2 朝颤音方向多走一倍（技巧被夸张化），γ=0 完全不管条件（落回平均歌声）。类比是调音台上的一个旋钮，往右拧特征被强调，拧过头就失真。

### 最聪明的一个设计

上面说训练时 10% 故意不给标签，这是 CFG 需要的。但论文给了第二个理由，这才是精彩的地方：**因为技巧标签本身就有错。**

这些标签不是人标的，是外挂一那个检测器自动标的，而它只有 83.3% 准确率，也就是每六个字大约有一个标错。如果模型 100% 相信标签，它会学到错的东西。而「有 10% 的时候标签会消失」这件事，恰好逼它不能把标签当圣旨，它必须同时具备没标签也能唱的能力，于是对标签的依赖是有弹性的。

**一个机制同时办成两件事**，论文里罕见的优雅。

### 外挂一：技巧检测器

四步。第一步从音频提三样原料：梅尔谱、F0、变化量特征（能量、气声度）。第二步过 U-Net，名字来自形状，先一层层压缩看大局再一层层放大回细节，目的是同时看到宏观和微观，类比是先退三米看构图再凑近看笔触。第三步过 Squeezeformer，一个从语音识别搬来的模型，专长是听懂一段声音里发生了什么。

**第四步最值得讲：把每一帧压成每个字。**

一个字占几十帧，而要输出的是「这个字用了颤音吗」这一个判断，所以必须合并。最笨的办法是取平均，但**颤音往往只出现在一个字的后半段**（先把音唱稳再开始抖），气声可能只在起音那一瞬间明显。整个字一平均，那几帧关键信息就被剩下的普通帧稀释掉了。类比是十分钟录音里只有三秒关键，取个平均那三秒就没了。

解法是让模型自己学哪几帧重要：给每帧打一个 0 到 1 的权重分，按权重加权平均，重要的帧保住，无关的压下去。这正是 [[pooling]] 里说的注意力池化。

分类结构是分组的：混声-假声、强度是两个三分类；气声、气泡音、颤音、咽音是四个二分类；滑音由乐谱规则判定（一个字对应多个音符即为滑音）。

### 外挂二：技巧预测器

一个**冻结的语言理解模型**（试了 BERT 和 FLAN-T5）加一个技巧解码器。冻结的意思是这个模型早就在海量文本上训好了，本来就懂人话，直接拿来用，训练时一个参数都不改，类比是雇一个现成的翻译。

两块靠 **cross-attention** 连接。大白话是解码器在决定第三个字该用什么技巧的时候，会回头看那句话里哪几个词跟这个决定有关，重点参考那几个，其他略过。类比是填表时每填一格回头看一眼说明书里相关的那句，而不是把整本背下来。

训练数据也是造的：GPT-4o 给每个技巧和歌手身份生成同义词，造 60 多个带空格的句式模板，随机填空拼句子。

### 两阶段训练

因为精修模型得先有粗图才能学怎么精修，而粗图是第一阶段的产物。第一阶段训整条流水线但不训精修，200k 步；第二阶段把第一阶段全部锁死，只训精修，120k 步。类比是先把起稿的人训好，等他能稳定起出像样的稿再训上色的人，两个人一起训的话起稿的一直在变，上色的永远学不会。

检测器和预测器另外单独训，120k 和 80k 步。**整套在一张 2080Ti 上跑完**，对比 TCSinger 的四张 3090Ti，算力预算小得多。

数据是 GTSinger 的中英西德法五个子集，加自采并标注的 30 小时中文（2 位歌手），再用训好的预测器加滑音规则去标注 M4Singer。测试集 804 段。

## 结论

技巧可控 SVS 主表（Table 1，所有基线都被加了音素级技巧 embedding 层才能参赛）：

| 方法 | MOS-Q↑ | MOS-C↑ | FFE↓ | MCD↓ |
|---|---|---|---|---|
| Reference | 4.54 | | | |
| Reference（过声码器） | 4.15 | 4.30 | 0.034 | 0.919 |
| DiffSinger | 3.59 | 3.84 | 0.255 | 3.897 |
| VISinger2 | 3.52 | 3.85 | 0.296 | 3.944 |
| StyleSinger | 3.69 | 3.93 | 0.328 | 3.981 |
| TechSinger | 3.89 | 4.10 | 0.245 | 3.823 |

值得注意的是 **StyleSinger 主观分最高但两个客观指标都最差**（FFE 0.328、MCD 3.981），主客观在这张表里明显不一致，论文没有讨论。

技巧序列的三种来源（Table 2），这是全篇最有力的一张表：人工标注真值 MOS-Q 3.89 / MOS-C 4.10，自然语言 prompt 预测 3.85 / 4.04，不给技巧让模型自由发挥 3.78 / 3.76。**prompt 几乎追平了真值**，说明「文字到技巧序列到歌声」这条链是通的，用户不需要懂音乐术语。

文本编码器（Table 3）：flan-t5-base 的 F1 0.817 / Acc 0.851 最优，flan-t5-large 是 0.818 / 0.846，bert-base 0.807 / 0.845，**bert-large 反而更差** 0.786 / 0.827。两条结论和 Prompt-Singer 完全吻合，可以当作被两篇独立验证过的经验：FLAN-T5 系整体优于 BERT 系，且规模收益很快饱和。

检测器消融（Table 4）：完整检测器 Precision 0.815 / Recall 0.761 / F1 0.770 / Acc 0.833；换成卷积 0.759 / 0.726 / 0.742 / 0.783；加权池化换成简单平均 0.807 / 0.756 / 0.763 / 0.831。结构的影响明显大于池化方式。

合成模型消融（Table 5，CMOS 以完整模型为 0 点，完整模型 FFE 0.2448）：去掉 FMPP 是 -0.25 / -0.23 / FFE 0.2537；去掉 postnet 是 -0.33 / -0.27 / 0.2680；去掉 CFG 是 -0.10 / -0.18 / 0.2453。**postnet 影响最大**，印证了粗解码器的 L2 损失不够。而 **CFG 单独拿掉时 FFE 几乎不变但可控性掉 0.18**，说明 CFG 买的是「技巧做得像不像」，不是「音高准不准」。

## 局限

**论文没有单独的 limitations 节**，只有一个 ethical statement。以下都是读出来的。

- **没有讨论自动标注误差如何向下传播。** 检测器 83.3% 的准确率是全篇最关键的数字，只在消融表里报了一次，正文没有分析它对最终 MOS-C 的影响上界。label dropout 只能让模型别太当真，不能把错的变对。
- **Table 3 的叙述与数据不符。** 正文写「FLAN-T5 的表现随编码器规模增大而提升」并据此选了 flan-t5-large，但表里 base 的 Precision 和 Acc 都比 large 高。选 large 未必错，但这个理由站不住。
- **StyleSinger 主客观指标相反**，论文未作解释，也就无法判断 MOS-C 这个主观指标本身有多可靠。
- **基线全部经过改造**，加了技巧 embedding 层才能参赛。这是这个组第三次这么做，读他们的论文要习惯性打折。
- **五种语言的分布未报告。** GTSinger 各语种时长本就不均（中文最多），自采的 30 小时是纯中文，M4Singer 也是中文。「支持五种语言」的实际水位很可能严重偏向中文，但论文没给分语种结果。
- **技巧预测器只用全局标签造 prompt，却要求输出音素级序列。** prompt 模板填的是「全局技巧标签、语言、身份」，从一句全局描述推出逐音素的安排，这个映射是高度欠定的。模型实际学到的很可能是「这类描述下技巧的典型分布」，而不是精确控制。Table 2 里 prompt 逼近真值的结果很漂亮，但也可能说明 MOS-C 对音素级位置并不敏感。
- **ODE 求解步数写得含糊。** 论文说向量场估计器是 100 steps，同段又说阶段一 200k 步、阶段二 120k 步，前者从上下文看应指采样步数，但表述不清。

## 对我意味着什么

- **标注瓶颈的三种解法已经集齐了。** 人工精标（GTSinger）、人工扩标（TCSinger）、模型自动标（TechSinger），代价分别是钱、不可知的质量、可量化的 83% 准确率。往后每篇 SVS 都先问一句：它的技巧标注从哪来。而且这条线还有下一步，STARS 把转写、对齐、风格标注统一成了一个框架。
- **评测任务可以变成生产工具。** GTSinger 把技巧识别当 benchmark，TechSinger 把它当标注器。这个转换很值钱，可以往别处套。
- **「直接回归会得到平均答案」是个通用陷阱。** 凡是「同一份输入有多个合法答案」的任务，用 L1 或 L2 直接回归都会塌成平均值。这条比 flow matching 本身更值得记，它解释了为什么生成式方法在这些任务上是必需品而不是花活。
- **flow matching 进 SVS 了，而且是从 TTS 搬过来的。** Voicebox 到 TechSinger 这条路径说明 TTS 的方法论会以大约一到两年的延迟传导到 SVS。想预测 SVS 下一步，看 TTS 现在在做什么。
- **CFG 的 label dropout 可以兼作噪声标签的鲁棒性手段。** 完全可迁移到任何「训练标签本身不可靠」的场景，包括我本科论文里那种伪标签设定。
- **加权池化优于平均池化，当信号只在少数帧出现时。** 这条直接对上 [[audio-ml]] 里那个 pooling 的坑，这篇给的是那个坑的正面解法。
- **FLAN-T5 优于 BERT、规模很快饱和，被两篇独立验证了。** 选文本编码器时可以直接用这条经验，不必再试。
