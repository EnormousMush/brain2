# Zhang 2024

**GTSinger: A Global Multi-Technique Singing Corpus with Realistic Music Scores for All Singing Tasks** · Yu Zhang, Changhao Pan, Wenxiang Guo 等（浙江大学，赵洲组）· NeurIPS 2024 Datasets & Benchmarks Track · https://arxiv.org/abs/2409.13832 · https://github.com/AaronZ345/GTSinger · https://huggingface.co/datasets/AaronZ345/GTSinger

## 它做了什么

数据集论文，不是模型论文。它问的不是「怎么生成得更像」，而是「歌声这个任务到底要标注什么」。

说话只需要控制内容和音色，唱歌多出三层：旋律（每个字在哪个音高上）、节奏（每个字唱多久）、技巧（同一个音，用真声还是假声、抖不抖、带不带气声）。前两层乐谱里本来就有，第三层在 GTSinger 之前没有任何公开数据集提供过。

规模：80.59 小时无伴奏歌声，是当时最大的**录制**歌声数据集（录的，不是爬的）。20 位专业歌手，覆盖四个声部（alto / soprano / tenor / bass），9 种语言（中英日韩俄西法德意），1,366 首歌，切成 29,261 条歌声片段，95% 落在 5 到 20 秒。48kHz / 24bit 专业录音棚，歌手戴耳机听伴奏，所以人声干净但节奏对得上。另有 16.16 小时配对朗读，即同一位歌手把同一句歌词说一遍，专供语音转歌声任务。协议 CC BY-NC-SA 4.0，非商用免费。

**核心设计一，对照组录音（controlled comparison）。** 同一位歌手、同一首歌、同一段歌词、同一个调、同一个录音棚，录两遍：一遍密集使用某个技巧（技巧组），一遍自然唱不用它（对照组）。假声和混声因为相关性强，共用一个对照组配两个技巧组，且假声版允许升调以便更好展示该技巧。这样一来技巧就成了两组之间唯一的自由变量。代价是录音量直接翻倍。

**核心设计二，技巧标在音素上。** 六种技巧：混声、假声、气声、咽音、颤音、滑音。标注粒度是音素级而不是句级或歌级，因为技巧本来就是音素的属性，一句歌里可能只有一个字的韵母用了颤音。标注是**六个独立的二分类**而不是六选一：技巧组里除了指定技巧还会自然出现别的技巧，对照组里也不是什么技巧都不用（歌手被要求自然唱）。对齐流程是 MFA 粗对齐后由有音乐背景的标注员用 Praat 逐条修，修边界是工作量大头，此外还要修歌手唱错的字、中文同音字、标出清音区（换气和静音）。另有全局风格标签：唱法（流行 / 美声）、情绪（喜 / 悲）、速度（慢 / 中 / 快）、音域（低 / 中 / 高）。

**核心设计三，真实乐谱（realistic music score）而不是细粒度乐谱。** 三个东西要分清：F0 是实际唱出来的逐帧音高曲线，带颤音带滑音带起音不稳；细粒度乐谱是从 F0 反推出来的音符，音高对但时值七零八落（人唱歌本来就不严格卡拍）；真实乐谱是音乐专家定好 tempo、调号、谱号之后按记谱规则规整过的，时值落在四分、八分这些规范值上，并标注音符类型（休止 / 歌词 / 连音），输出 musicxml。制作流程是 RMVPE 抽 F0，ROSVOT 转 MIDI，再由音乐专家听原曲、参照原伴奏逐条修。理由是训练输入必须和推理输入同分布：真实场景里作曲家给的是正谱，模型若只见过细粒度乐谱就用不上。OpenCpop 和 M4Singer 已经有人工对齐和乐谱，但只有细粒度乐谱，这是 GTSinger 相对它们的主要增量。

后处理还有一道抽检：每种语言另请一位精通该语言的音乐专家随机检查 25% 的标注。

统计上，混声出现最多（流行和美声都常用），颤音最少（只能用在长音上，密度天然低）。BPM 主要在 80 到 150，音符音高主要在 MIDI 50（D3, 146.83 Hz）到 70（B4, 494 Hz）。

## 结论

作者跑了四个 benchmark 来证明数据集撑得起哪些任务，全部用 4 张 2080Ti，声码器统一 HiFi-GAN。

技巧可控 SVS（Table 3，parallel 设定）：

| 方法 | FFE↓ | MCD↓ | MOS-Q↑ | MOS-C↑ |
|---|---|---|---|---|
| GT（真人） | | | 4.54 | 4.42 |
| GT（过声码器） | 0.05 | 1.33 | 4.21 | |
| DiffSinger | 0.29 | 3.58 | 3.81 | 3.83 |
| RMSSinger | 0.27 | 3.43 | 3.94 | 3.95 |
| StyleSinger | 0.25 | 3.27 | 4.01 | 4.15 |

MOS-C（技巧可控性的人耳打分）是这篇才有的指标，因为以前没有数据集能做这件事。这张表最值钱的一行洞察是 DiffSinger 到 RMSSinger 的差：RMSSinger 用扩散模型专门建模 F0，MOS-C 就从 3.83 涨到 3.95，论文由此断言音高建模能力直接决定技巧表现力。这条在物理上讲得通，颤音本质是 F0 的周期性波动，滑音本质是 F0 的连续过渡，六种技巧里至少两种就是 F0 的形状。

技巧识别（Table 4，音素级六个二分类，模型基于 ROSVOT 改，损失换成每个技巧标签的交叉熵，输入是梅尔谱 + 音高 + 音素边界）：整体 F1 依次是混声 0.78、假声 0.96、气声 0.99、咽音 0.85、颤音 0.70、滑音 0.70。跨语言实验（亚洲语言训练、欧洲语言测试，及反向）全线下降但幅度很小，F1 最多掉 0.06（滑音 0.70 到 0.64），说明技巧是跨语言的物理现象，不依赖具体语种。

风格迁移（Table 5，parallel）：StyleSinger 的 FFE 0.26、MCD 3.29、Cos 0.93、MOS-Q 3.95、MOS-S 4.01，优于 RMSSinger 的 0.31 / 3.47 / 0.88 / 3.70 / 3.79。

语音转歌声（Table 6）：StyleSinger 的 FFE 0.28、MCD 3.38、Cos 0.92、MOS-Q 3.83、MOS-S 3.88，优于 AlignSTS 的 0.35 / 3.52 / 0.85 / 3.68 / 3.73。

四个任务的共同结论是同一个：SOTA 离 GT 过声码器还差着（技巧可控 SVS 上 4.01 对 4.21），离真人差得更远（4.54）。作者在每一节都用 ample room for improvement 这句话，等于把后续工作的位置留好了。

## 局限

- 作者自己承认的覆盖不全：语言缺阿拉伯语等，技巧缺气泡音（vocal fry）等。
- 作者自己承认的标注误差：音素时长的精确切分和细微技巧的辨认，对人耳本来就难。这一条对数据集论文杀伤力不小，因为整个数据集的价值建立在标注可信上，而抽检只覆盖 25%。
- 语音转歌声那组对比不完全公平：AlignSTS 需要真实歌声 F0 当输入，StyleSinger 用的是真实乐谱。论文的论点（用乐谱更实用，因为一首没人唱过的歌哪来的真实 F0）站得住，但两个系统吃的输入根本不同，指标不能直接横比。
- 「技巧组密集使用某技巧」是个模糊的量。密集到什么程度没有量化标准，全靠歌手执行和标注员判断，不同技巧、不同歌手之间的密度未必可比。
- Table 3 的三个基线（DiffSinger、RMSSinger、StyleSinger）都是被作者额外接上音素级技巧 embedding 之后才能做技巧控制的，不是原生支持。所以那张表量的是「这几个模型接上技巧条件之后的表现」，不完全等于模型本身的高下。
- 每位歌手只精通一种语言，所以「语言」和「歌手」这两个变量在数据集层面是绑定的。跨语言实验里，语言的影响和歌手的影响没有被分开。

## 对我意味着什么

- **给了 SVS 的任务坐标系。** 技巧可控 SVS、技巧识别、风格迁移、语音转歌声，后面九篇 SVS 论文基本都落在这四个格子里，先分类再读会快很多。
- **对照组录音这一招，和我本科论文里的 Deezer 重建法是同一个思想。** 都是从数据构造上把混淆变量消灭掉，而不是事后去对齐分布。Deezer 是同一首歌的原版和 autoencoder 重建版，唯一差别是过没过神经解码器；GTSinger 是同一首歌的技巧组和对照组，唯一差别是用没用某个技巧。要学会的通用招式是：想让模型学会某个属性，就想办法让那个属性成为数据里唯一的自由变量。见 [[confounder]]。
- **标注粒度决定控制粒度。** 想在哪一级控制，就得在哪一级标注。这条比论文本身通用得多。
- **F0 建模是 SVS 的命门。** 往后每读一篇 SVS，先问它怎么处理 F0：用什么建模、在哪一层注入、是显式预测还是隐式学。
- **Table 4 里颤音那一列是我 [[evaluation-metrics]] 笔记的真实案例。** Accuracy 0.89 但 F1 只有 0.70。颤音是全数据集最稀有的技巧，模型偏向猜「没有」就能刷高 Accuracy，F1 才把它戳穿。我笔记里那个 1% 发病率的例子在这里原样复现了。
- **和前五篇的接口。** Fan 2026 那个「表征 + 生成器 + 条件」三元组里，GTSinger 填的是第三格「条件」，而且填的是歌声特有的那些条件（乐谱、音素、技巧标签）。表征那格是两篇 tokenizer 论文，生成器那格是 VALL-E、NS2、Voicebox。
