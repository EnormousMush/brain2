# Zheng 2026

**UniVoice: A Unified Model for Speech and Singing Voice Generation** · Junjie Zheng, Chaofan Ding, Zihao Chen（巨人网络）, Huixin Xue, Shihong Ren, Hao Liu（上海音乐学院）· arXiv:2606.05852v1，Preprint · https://arxiv.org/abs/2606.05852 · https://nips-unvoice.netlify.app/

## 它做了什么

和 Vevo2 回答同一个问题：语音和歌声能不能用一个模型。解法正好相反。

**困境是共同的**：唱歌需要旋律作为强约束，生成的声音必须跟着给定音高和时值走；说话则相反，强加一条旋律没必要且会限制自然的、依上下文变化的韵律。把两种数据混在一起硬训，等于强迫模型给旋律相关的条件赋予两种互不相容的含义，造成梯度干扰。

| | Vevo2 | UniVoice |
|---|---|---|
| 思路 | 找一种两边通用的表示 | 承认两边不同，分开建模 |
| 旋律怎么表示 | 色度图（去八度，语音歌声共用） | MIDI 音符序列（只给歌声） |
| 语音怎么办 | 同一个色度 token，EPL / IPL 随机切换 | 换成一个可学的空旋律 token |
| 骨干 | 自回归 Transformer + 流匹配 | 纯流匹配 DiT（Wan-DiT） |
| 规模 | 872M，101k 语音 + 7k 歌声 | 0.3B，30k 语音 + **35k 歌声** |

**35,000 小时歌声比 Vevo2 的 7,000 还多五倍**，来源是野生歌曲人声分离加录音棚干声，歌词靠 ASR 交叉验证（有 SRT 时）或 VAD 加 ASR 对齐，再过规则清洗；**MIDI 由一个预训练的提取模型自动生成**。语音取自 Emilia 的 30k 小时子集（中英各 15k）。语音和歌声共用一套 IPA 音素系统。注意它虽然用 MIDI 当旋律条件，但 MIDI 本身也是自动抽的，并没有回到依赖专家标注的路子，只是把自动抽取放在数据准备阶段而不是像 Vevo2 那样放进表示设计。

### 因子化条件，以及对梯度冲突的具体诊断

论文对冲突的诊断比 Vevo2 具体：用一个不分化的编码器时，语音和歌声会在旋律相关的参数上产生**负梯度相关**。**语音把旋律参数推向一个常数函数**（因为语音里旋律条件没有意义，最省事的解是忽略它），**歌声把同一批参数推向忠实编码 MIDI**。两股力量方向相反、互相抵消。

解法是把条件拆成四路，各有独立编码器：内容 c_cnt（ConvNeXt，IPA 音素）、旋律 c_mel（Conformer，MIDI 音符，语音时换成空 token）、音色 c_tmb（3 到 10 秒音频 prompt 的 VAE latent）、任务 c_tsk（可学的 speech / singing token）。因子化之后旋律编码器只从歌声接收梯度，空 token 只从语音接收梯度，两条通路物理隔开。论文写成 Proposition 1：在「给定内容和音色时旋律与语音音频近似条件独立」的假设下，因子化消除了旋律子空间上的负向跨任务交互。

其他设计：**拼接融合而非 cross-attention**，四路条件沿通道与带噪 latent 拼接后线性投影，让 DiT 用自注意力自己学跨模态交互；**任务 token 经 AdaLN 注入**，c = c_time + c_tsk，这样区分两个模态不需要在主计算路径里加任何任务专用参数；**按轴分别的 CFG**，训练时以各 0.1 的概率独立丢弃文本、旋律、音色三路，推理时可对每一轴分别施加引导强度，比 TechSinger 那种单一 CFG 细一档。骨干选 Wan-DiT（视频生成架构）24 层，配 RoPE 和 FlashAttention-2，理由是音视频联合生成的管线里视频分支通常就是 Wan-DiT 家族，用同样架构方便日后接进去。在 Song Bloom VAE 的 latent 上工作，25 Hz、48 维，Euler ODE 32 步，8 张 A800。

### 空旋律 token

生成语音时把旋律条件那一路换成一个**可学的**向量 e∅，不是简单填零。

论文的理论解释是这可以理解为**对旋律变量做边缘化的近似**：生成语音时我们并不知道也不关心旋律是什么，理论上正确的做法是对所有可能的旋律取平均，但枚举不现实，所以用一个学出来的向量去近似那个平均后的结果。

**这就是为什么填零不如学一个：零向量代表「旋律是零」，e∅ 代表「旋律是什么都行」。** 这两件事完全不同。这个区分在别处也成立，凡是「某个条件在某些样本上不适用」的场景，用一个专门的可学 token 表示「不适用」，通常好过填零或直接省略。TechSinger 的 CFG 里那个无条件标签 2 是同一个思路的近亲。

## 结论

主表（PER 为音素错误率，用 FireRedASR 测；SIM 为 WavLM 说话人嵌入余弦相似度）：

| 模型 | 参数 | 数据（语音+歌声） | 语音 PER↓ | 语音 SIM↑ | 歌声 PER↓ | 歌声 SIM↑ | 歌声 N-MOS↑ |
|---|---|---|---|---|---|---|---|
| F5-TTS | 0.3B | 100k + 0 | 5.21 | 72.73 | | | |
| CosyVoice3 | 0.5B | 1000k + 0 | 5.30 | 74.94 | | | |
| Vevo1.5 / Vevo2 | 1B | 101k + 7k | 14.10 | 59.07 | 45.07 | 36.33 | 2.69 |
| Soul-X-Singer | 0.7B | 0 + 42k | | | 26.22 | **41.71** | 3.24 |
| UniVoice | **0.3B** | 30k + 35k | 5.26 | 67.42 | **16.22** | 35.70 | **3.25** |

语音上追平了纯 TTS 系统（5.26 对 F5-TTS 5.21、CosyVoice3 5.30），而 CosyVoice3 用了一百万小时语音、UniVoice 只用 30k 小时和 0.3B 参数。歌声上大幅领先专用模型（PER 16.22 对 Soul-X-Singer 26.22）。

**但论文没提的一点：歌声任务上 UniVoice 的音色相似度（35.70）是三个系统里最低的**（Vevo 那栏 36.33，Soul-X-Singer 41.71）。正文写「PER 16.22、SIM 35.70，大幅超越 Vevo1.5 和 Soul-X-Singer」，把两个数并列说，但只有 PER 是领先的。作者在 limitations 里承认了统一训练相对纯语音系统存在 SIM gap，但那说的是语音，歌声上落后于专用模型这点正文没单独指出。

消融（Table 2）：

| 配置 | 语音 PER↓ | 歌声 PER↓ | 歌声 S-MOS↑ |
|---|---|---|---|
| 完整模型 | 5.26 | 16.22 | 3.19 |
| w/o 因子化条件 | **12.31** | **23.45** | 2.23 |
| w/o 任务 token | 8.34 | 19.92 | 3.01 |
| w/o 可学空旋律 token | 7.86 | 18.64 | 3.06 |
| w/o 旋律编码器 | 6.27 | 23.21 | **2.03** |

**最后一行是全篇最漂亮的证据：去掉旋律编码器，语音几乎没事（5.26 到 6.27），歌声崩了（S-MOS 3.19 到 2.03，掉 1.16 分，是全表最大的单项降幅）。** 这直接验证了因子化的核心论点：旋律那条轴只服务于歌声，对语音基本无用；既然对语音无用，让它同时接收语音的梯度就是纯粹的干扰。

「可学的空 token 比填零好」也被验证：换成固定零向量后语音 PER 从 5.26 退到 7.86，歌声从 16.22 退到 18.64。

副产品是提出了 **UniSinging-Eval** 基准：60 首歌覆盖 12 种音乐风格，IPA 转写歌词，900 个样本共 2 小时，带短语级时间戳和风格元数据，并组织成三种歌词变化以测试鲁棒性。

## 局限

**作者承认的：** 统一训练相对纯语音系统仍有 SIM gap，说明跨模态共享和音色相似度之间存在取舍；只评测了英文和中文；说唱、念白这类混合风格没有显式建模；32 步 ODE 采样带来较高延迟。

以下是读出来的。

- **它对 Vevo2 的描述不准确。** 论文在 related work 里写 Vevo2 用「刚性的 F0 约束」，但 **Vevo2 明确说了它不用 F0**，它用色度图，而且给出的三条理由里第一条就是语音和歌声的 F0 分布差距很大所以要用去八度的色度图抹平。它选色度图恰恰是为了避开 F0 的问题，而 UniVoice 把这个问题按在它头上。命名也对不上：摘要和基线表写 Vevo1.5、正文写 Vevo2，用的是同一个数字（PER 24.72，另一处 45.07），而基线表标的「101k + 7k 小时」和 Vevo2 论文完全一致、参数量标 1B 而 Vevo2 自报 872M。大概率比的就是 Vevo2，名字和描述都写错了。
- **跨论文的数字不能直接比，这里有个现成实例。** Vevo2 自己那篇报告的歌声 WER 是 7.66（后训练之后），这里报的 Vevo 歌声 PER 是 45.07，差近六倍。原因是指标不同（WER 是词错误率，PER 是音素错误率）、测试集不同（Vevo2 用 GTSinger 加 SingStyle111，这里用自建的 UniSinging-Eval），可能连模型版本都不同。见 [[evaluation-metrics]]。
- **歌声 SIM 垫底但正文未指出**，上面已说。
- **35k 小时歌声的构建细节很薄。** 只说了野生分离加录音棚干声、ASR 对齐、规则清洗，没给出各来源占比、清洗掉多少、以及 **MIDI 提取模型的准确率**。而 MIDI 提取的准确率直接决定旋律条件的质量，这个数字缺失比较关键。
- **Proposition 1 的条件独立假设没有被验证**，只是作为假设提出。
- **没有做「只训语音」「只训歌声」的对照。** 消融拆的全是条件设计，而 Vevo2 恰恰做了数据配比的对照并得出「只用歌声训反而更差」这样的反直觉结论，两篇在这一点上互补。
- **Soul-X-Singer 作为基线只报了歌声**（合理，它是专用模型），因此「统一模型能否打过专用模型」这个问题只在歌声一侧有答案。

## 对我意味着什么

- **「统一」有两种做法，两篇都拿出了证据，这是一组现成的对照。** Vevo2 抹平差异（找通用表示），UniVoice 保留差异（分开建模）。代价分别是丢掉绝对音高导致旋律精度下降、以及多一个 MIDI 提取模型作为误差来源。验证方式也互补：Vevo2 做数据配比消融，UniVoice 做条件组件消融。给学姐的报告里这组对照可以直接用。
- **「可学的空 token」比「填零」好，是个可迁移的小结论。** 零代表「值为零」，学出来的 token 代表「这一路不适用」。凡是某个条件在部分样本上不适用的场景都能套。
- **因子化条件的收益能被消融量化。** 去掉因子化，语音 PER 翻倍还多（5.26 到 12.31），歌声退 7 个点。这比笼统说「解耦有用」有力得多。而「去掉旋律编码器只伤歌声不伤语音」这条更是把因子化的动机直接证成了。
- **按轴分别的 CFG 是个细化方向。** TechSinger 是一个 γ 控全局，这篇是文本、旋律、音色各有各的引导强度。
- **跨论文比数字很危险，这是我读到现在最清楚的实例。** 同一个模型在两篇论文里的数字差近六倍。往后给学姐的报告里，凡是引用某个模型的数字，必须带上出自哪篇、哪个测试集、什么指标。
- **跟学姐工作的接口：因子化条件加任务 token 这个结构跟她的全曲生成场景直接对应。** 她同样面对多种条件（歌词、caption、音乐属性、参考音频）和多个任务（词生歌、纯器乐、翻唱），而「纯器乐」恰好是「没有歌词条件」的情形，用一个可学的空 token 表示「这里没有人声」可能比其他处理方式更干净。另外 Wan-DiT 骨干的选择理由（方便日后接进音视频联合生成管线）也值得留意。
