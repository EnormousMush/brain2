# Shen 2023

**NaturalSpeech 2: Latent Diffusion Models are Natural and Zero-Shot Speech and Singing Synthesizers** · Kai Shen, Zeqian Ju, Xu Tan 等（Microsoft Research Asia & Azure Speech）· ICLR 2024 · https://arxiv.org/abs/2304.09116 · demo https://speechresearch.github.io/naturalspeech2 · 官方未开源

## 它做了什么

**核心动作是把中间表示从离散 token 换成连续 [[latent]]，把生成器从自回归语言模型换成扩散模型。** 同一家公司（微软）在 VALL-E 之后三个月发的，是对那条路线的正面回应。

**论证起点是一个两难困境**（论文 Table 2）。用离散 token 做语音生成，必然被夹在中间：每帧只用 1 个 token（VQ）则序列短、语言模型好生成，但压得太狠丢高频细节；每帧用多个 token（RVQ）则重建保真，但序列长 R 倍，自回归模型开始误差传播、丢词重复。AudioLM 和 VALL-E 的两阶段做法是绕，论文评价是复杂且级联误差。NS2 直接不走离散这条路。

**Codec 也用 RVQ，但目的完全不同。** 它用很多层量化器把各层残差向量**求和**成一个逼近连续的向量，每帧只有一个向量而不是多个 token，序列长度不变成 R 倍。论文自己坦承要得到连续向量根本不需要量化器，autoencoder 或 [[vae]] 就行，用 RVQ 纯粹是两个工程理由：训扩散模型时只存码本和 token ID 省内存，以及有了 ID 就能加一个分类损失当正则。卷积编码器，16 kHz，下采样率 200，每帧 12.5 毫秒。

**扩散模型**用 SDE 描述前向加噪和反向去噪（也可走 ODE 加速），骨干是 40 层 WaveNet。一个实践选择是网络直接预测干净数据 ẑ₀ 而不是预测 score，论文说这样语音质量更好。损失有三项：数据损失、score 损失，加上新提出的 `L_ce-rvq`（权重 0.1）。后者的做法是对每层量化器算预测残差与该层码本各条目的 L2 距离，softmax 成概率再跟真值 ID 算交叉熵，**等于在连续回归任务上额外挂一个离散分类任务当约束**。

**Prior 模型是通往歌声的关键。** 音素编码器（6 层 Transformer，FFN 换成卷积）出音素向量，时长预测器算出每个音素占几帧并据此展开到帧级，音高预测器再逐帧加上音高，得到条件 c。训练用真值时长和音高，推理用预测的。总损失 `L = L_diff + L_dur + L_pitch`。

时长预测器不是可选项而是刚需：**扩散是整块一起生成的，必须事先知道要生成多少帧**，不像自回归可以自己吐 `<EOS>`。这个被迫加进来的模块，连带把音高也做成了显式条件。

**Speech prompting 有个信息瓶颈设计。** 训练时从目标语音自己身上随机切一段当 prompt，剩下前后拼起来当预测目标，推理时换成参考录音。注入方式两个模块不同：时长/音高预测器直接插 Q-K-V 注意力；扩散模型则走**两级注意力**，第一级用 m=32 个随机初始化的 query 去 attend prompt 压成固定长度 32，第二级才让 WaveNet 的 hidden 去 attend 那 32 个结果，最后过 FiLM 层。理由是直接 attend prompt hidden 会**暴露太多细节反而伤害生成**。

数据是 MLS 英文子集 4.4 万小时（2742 男 + 2748 女），另加约 30 小时爬来的歌声（去伴奏、ASR 过滤）。模型 400M 参数。codec 用 8 张 V100 训 440K 步，扩散用 16 张 V100 训 300K 步。推理温度 τ=1.2²，Euler ODE 求解器，扩散 150 步（唱歌 1000 步）。

## 结论

**自然度与相似度**（基线 YourTTS，测试说话人未见过）：

| 指标 | 数据集 | YourTTS | NS2 | 真人 |
|---|---|---|---|---|
| CMOS（对比 NS2） | LibriSpeech | −0.65 | 0.00 | +0.04 |
| CMOS | VCTK | −0.58 | 0.00 | **−0.30** |
| SMOS | LibriSpeech | 2.03 | 3.28 | 3.33 |
| SMOS | VCTK | 2.43 | 3.20 | 3.86 |
| WER ↓ | LibriSpeech | 7.10 | 2.26 | 1.94 |
| WER ↓ | VCTK | 14.80 | **6.99** | 9.49 |

两个反常格子：VCTK 上真人录音的 CMOS 是 −0.30，也就是 NS2 明显比真人更自然；WER 也比真人低。论文的解释是 VCTK 录音环境有噪声而合成语音干净。

**最硬的一张表是鲁棒性**（FastSpeech 那 50 个特别难的句子）。自回归模型 Tacotron 错误率 24%、Transformer TTS 34%，论文明说 VALL-E 在这些句子上同样错误率高；而 FastSpeech、NaturalSpeech、NaturalSpeech 2 三个非自回归模型**全都是 0%**，零重复零丢词。直接对比 VALL-E（取它 demo 页 16 条样例）：SMOS 3.83 对 3.53，CMOS 领先 0.31。

**消融显示 speech prompt 是命根子**。去掉扩散模型的 prompt，模型**直接不收敛**；去掉时长/音高预测器的 prompt，韵律相似度（音高均值差）从 10.11 翻倍到 21.69；去掉 `L_ce-rvq` 和去掉那 32 个 query token 各自小幅变差（10.69 和 10.78），后者印证了细节泄漏有害。prompt 长度 3 秒 → 10.11、5 秒 → 6.96、10 秒 → 6.90，越长越像但 5 秒后收益递减。

**零样本歌声合成是这篇最重要的结果。** 只用约 30 小时爬来的歌声混进语音数据一起训（学习率降到 5e-5），合成时用**另一段歌声的真值音高和时长**当条件，配不同 prompt 决定音色。除了拿歌声当 prompt，**还可以只给一段说话的 prompt 就生成唱歌**，论文称之为 truly zero-shot singing synthesis。

## 局限

- **论文自己承认模型还欠拟合**，只训了 300K 步，说训更久会更好。这意味着表里的数字不是架构上限，但也意味着对比不完全公平。
- **歌声数据只有 30 小时而且是爬的。**「说话 prompt 生成唱歌」这个结论建立在很薄的数据上，泛化到什么程度未知，demo 页只有精选样例。
- **依赖外部的时长和音高标注**（内部对齐工具 + PyWorld）。这是真实的工程负担，对齐工具质量直接决定上限，后来一整条研究线在想办法去掉它。
- **推理慢。** 150 步扩散、唱歌 1000 步，跟自回归比没有速度优势，跟后来的 flow matching 更是慢一个量级。
- **韵律相似度这个指标很间接。** 它算的是音高和时长的均值、标准差、偏度、峰度之差，不如 VALL-E 用的说话人相似度直观，也不好跨论文比较。
- **未开源**，又一篇只有 demo 页的微软论文。

## 对我意味着什么

- **这是通往 SVS 的那座桥，也是本次调研 foundation 里跟歌声最直接相关的一篇。** 三元组填法：表征 = 连续 latent（RVQ 只用来省内存和正则），生成器 = 隐扩散（WaveNet 骨干，150 步），条件 = 音素 + 显式时长 + 显式音高 + speech prompt。
- **最该带走的一条：NS2 把「说什么、多快说、什么音高、谁在说」拆成了四个可以分别替换的入口。** VALL-E 只拆成两个（内容、音色），音高和节奏是模型顺带生成的、控制不了。多拆出来的那两个入口代价是需要额外标注和预测器，回报是**你能把音高换成一条歌的旋律**。后面 9 篇 SVS 论文本质上都在细化这个分解：旋律怎么给、风格怎么给、唱法技巧怎么给。
- **「离散 vs 连续」这条轴到今天没有收敛。** VALL-E 选离散，NS2 选连续；后来 Voicebox 和 F5-TTS 走连续加 flow matching，CosyVoice 和 MOSS 走离散加自回归。读后面每一篇时都可以先问它站哪边、为什么。
- **信息瓶颈那个设计要记住。** 「怕参考音频泄漏太多细节」在 SVC 那边有个专门的名字叫音色泄漏，是那个领域近三年的头号矛盾。NS2 用瓶颈，Seed-VC 用训练时故意扰动，FACodec 用架构隔离，**同一个问题三种解法**。
- **扩散必须提前知道生成长度**，这个约束值得记牢。它解释了为什么非自回归路线一定要配时长预测器，也解释了为什么后来 DiTSinger 那类工作要费劲去掉时长标注。
