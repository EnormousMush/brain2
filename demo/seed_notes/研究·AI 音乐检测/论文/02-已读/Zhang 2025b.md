# Zhang 2025b

**Vevo2: A Unified and Controllable Framework for Speech and Singing Voice Generation** · Xueyao Zhang, Junan Zhang, Yuancheng Wang, Chaoren Wang（香港中文大学深圳）, Yuanzhe Chen, Dongya Jia, Zhuo Chen（字节 Seed）, Zhizheng Wu（通讯，港中深 / Amphion）· arXiv:2508.16332（期刊格式，投稿中）· https://arxiv.org/abs/2508.16332 · https://versasinger.github.io/ · https://github.com/open-mmlab/Amphion

注：文件名的 b 后缀是为了和 `Zhang 2025`（TCSinger 2，Yu Zhang）区分，两者是不同的人，只是同姓同年。

## 它做了什么

换了个组，也换了个世界观。前面五篇 SVS 都在 268 小时数据上精雕细琢，这篇用了 **7,000 小时歌声加 101,000 小时语音**。差别不在算力，在一个决定：**不要乐谱**。

那 7,000 小时歌声来自 SingNet 的流水线，从互联网上的野生歌曲做人声分离得到，不是任何一个标注过的数据集。以前没人这么干，是因为以前的模型必须要乐谱，而网上扒来的人声没有 MIDI、没有音素边界、没有技巧标注，对赵洲组那条线的所有模型来说这份数据是废的。

**它对病根的诊断是我读到现在最准的一句**：现有歌声语料严重依赖专家标注（歌词与音符精确对齐的乐谱），这些数据集本身稀缺，而且**它们独特的数据组织方式与大规模语音语料天生不兼容**，因此限制了可扩展性和统一训练。拆开说就是：不只是数据少，是数据的形状不对。歌声数据集是「音频 + 乐谱 + 音素边界 + 技巧标签」的四元组，语音语料是「音频 + 文本」的二元组，两者拼不到一起，所以既扩不了也没法统一训练。

它的假设是双向的：语音数据量大可以补歌声的不足；歌声表现力强能提升表达性语音，而且歌声有严格的旋律结构，学它能提升整体的韵律跟随能力。第二条尤其反直觉，后面 Table I 证实了。

### 色度图，全篇的地基

要做到不要乐谱，得回答旋律信息从哪来。答案是 **chromagram（色度图）**：把所有八度折叠起来，只看十二个音级（C 到 B）上各有多少能量。C3、C4、C5 都算作 C，所以男低音和女高音唱同一段旋律，色度图几乎一样。

我自己合成了三段验证：同一条旋律的人声原调（F0 均值 317.5 Hz）、人声高八度（637.7 Hz，正好 2.01 倍）、钢琴原调（320.2 Hz，音色完全不同）。色度图余弦相似度是原调对高八度 0.956、人声对钢琴 0.961，三者前三强的音级都是 C、E、G，正是旋律用的音。

论文给了三条理由，每条对应上面演示的一个方面：**去八度所以适合统一**（说话和唱歌的 F0 分布差距很大，去掉八度信息后跨域的共同韵律模式好抓）；**不要记谱所以适合放大规模**（能自动从音频抽取，无需人工转写）；**跨音频类型鲁棒**（是频谱能量的统计分布，对噪声和音高检测误差不敏感，对乐器也给得出好表示）。

第三条直接解锁了哼唱转歌声和乐器转歌声两个新任务。还有个精妙用法：要做常规 SVS 时，先把 MIDI 渲染成钢琴音，再从这段钢琴音里抽色度 token，**模型自始至终没直接见过乐谱**。

### 两个 tokenizer

结构同构：降采样 CNN、编码器、单码本 VQ、解码器、上采样 CNN，VQ 采用低维码查表加 L2 归一化。差别在重建目标和帧率。

- **韵律 tokenizer**：重建色度图，50 Hz 色度特征降采样 8 倍，得到 **6.25 Hz（56.25 bps）**。
- **内容风格 tokenizer**：重建色度图**加上 Whisper 隐特征**，50 Hz 降采样 4 倍，得到 **12.5 Hz（175 bps）**。装语言内容、韵律、风格，且音色被解耦掉。

为什么要同时重建色度图和 Whisper 特征：Whisper 是语音识别模型，隐特征擅长装「说了什么」，但对歌声旋律建模有短板，色度图正好补上。两个帧率保持严格的 2:1 关系，副产品是推理时可以直接控制生成时长。

### EPL 和 IPL

统一语音和歌声的真正难点在内容风格建模阶段：TTS 通常只给文本、不显式控制韵律，而 SVS 必须显式控制旋律，两者的生成范式根本不同。

解法是两种训练模式随机切换。**IPL（隐式韵律学习）**只给文本，韵律靠上下文学习自己推；**EPL（显式韵律学习）**额外给韵律 token。关键在于**不做区分**  论文特意说明不是「语音用 IPL、歌声用 EPL」，而是对每个训练样本以相同概率随机选一种，这样才真正统一了训练模式而不是把它们当两个任务。

### 两阶段生成加 GRPO 后训练

阶段一是自回归 Transformer（509M，从 Qwen2.5-0.5B 扩词表来），输入文本加韵律源加风格参考，输出内容风格 token，管文本、韵律、风格的可控性。阶段二是流匹配 Transformer（363M，16 层 16 头 hidden 1024），输入内容风格 token 加音色参考，输出梅尔谱，管音色控制，再过 Vocos 声码器（255M）出波形。总参数 872M。

flow matching 第四次出现（Voicebox、TechSinger、TCSinger 2、这篇）。可以下结论了：**自回归管内容和风格加流匹配管声学，已经是这个领域的标准架构。**

**GRPO 多目标后训练**是赵洲组那条线完全没有的东西。两个奖励：可懂度奖励（用 INTP 这个含 25 万对偏好数据的零样本 TTS 语料训一个奖励模型）和韵律相似度奖励。两者各自组内归一化后相加，用 GRPO 训练。论文明说为什么要两个目标一起：**防止模型过度优化单一目标**。后训练的韵律提示有三类：2 万条语音、2 万条 M4Singer 歌声、以及从 M4Singer 的 MIDI 渲染出的乐器音（16 种乐器五大类）。最后这类是关键，因为预训练时模型没见过乐器音，而 SVS 任务恰恰要用 MIDI 渲染的乐器音当韵律源。

算力：预训练 8 张 A100 跑 500K 步（约 168 小时），FM 模型 8 张 A100 跑 700K 步（约 168 小时），后训练 9K 步（约 48 小时）。

## 结论

**互相受益被一个干净的三行对照证实（Table I，同一个 872M 模型，都没做后训练）：**

| 预训练数据 | 表现力语音 WER↓ | SIM↑ | N-CMOS↑ | 歌声 WER↓ | SIM↑ | N-CMOS↑ |
|---|---|---|---|---|---|---|
| 只用语音 101K | 15.52 | 0.677 | -0.84 | 19.39 | 0.658 | -1.02 |
| 只用歌声 7K | 37.57 | 0.611 | -1.25 | 25.38 | 0.692 | -0.69 |
| 两个都用 | 14.32 | 0.681 | -0.49 | 15.78 | 0.708 | -0.28 |

**最反直觉的一行：只用 7,000 小时歌声数据训，歌声任务的可懂度（WER 25.38）反而比只用语音数据训（19.39）更差**，论文归因于歌声语料还是太小。两个都用时歌声 WER 降到 15.78，而语音那边同时受益（15.52 到 14.32）。这就是双向的互相受益。

**后训练的效果是全篇最戏剧性的数字**：Vevo2-base 到 Vevo2 之后，表现力语音 WER 从 14.32 降到 11.48，**歌声 WER 从 15.78 降到 7.66**，砍掉一半以上。只用了 9K 步 48 小时，对比预训练的 500K 步 168 小时，性价比高得惊人。

零样本 SVS 正面对比（Table II）：

| 模型 | 参数 | 英文 WER↓ | SIM↑ | FPC↑ | Melody-MOS↑ | 中文 WER↓ | SIM↑ | Melody-MOS↑ |
|---|---|---|---|---|---|---|---|---|
| Ground Truth | | 17.89 | 0.640 | 0.815 | | 7.40 | 0.675 | |
| StyleSinger | 42M | | | | | 14.04 | 0.555 | 2.33 |
| TCSinger | 330M | 40.83 | 0.605 | 0.724 | **2.55** | 14.26 | 0.651 | **2.58** |
| Vevo2-base | 872M | 60.83 | 0.586 | 0.719 | | 23.60 | 0.653 | |
| Vevo2 | 872M | 24.77 | 0.643 | 0.752 | 2.29 | 9.83 | 0.669 | 2.44 |

Vevo2 在可懂度、音色相似度、F0 相关性上全面领先，**但在 Melody-MOS 上输给 TCSinger**（英文 2.29 对 2.55，中文 2.44 对 2.58）。这正是不要乐谱的代价：TCSinger 直接吃 MIDI 音符信息精确，Vevo2 要先渲染成钢琴音再抽色度 token，隔了两道，旋律细节必然有损。论文的自辩是两个语言都超过 2.0，即大致能跟上旋律轮廓，这个自辩诚实，也说明了取舍的位置。

Table I 的基线里有 MaskGCT、F5-TTS、CosyVoice 2，都在我 folder 的 TTS 清单里（TTS/02、03、04），读到那几篇时可以回头对照。

## 局限

- **旋律精度是明确的代价。** Melody-MOS 输给 TCSinger。对需要精确音准的场景（专业音乐制作）这是硬伤。
- **7,000 小时数据的质量不透明。** 来自互联网野生歌曲的人声分离，分离残留、伴奏泄漏、版权状况都没有说明，而这是全篇最大的资产。
- **生成的歌声 WER（7.66）比真人（12.65）还低，论文未讨论。** 这不是超越人类，而是说明 **WER 在歌声上不是「越接近真值越好」的指标**：生成的歌声往往咬字过于清晰规整，更容易被 ASR 识别，而真人唱歌会连读、会含糊、会为情绪牺牲清晰度。看到 WER 低于 GT 时合理的解读是可能存在过度咬字，而非质量更好。
- **色度图去掉八度是双刃剑。** 它让统一成为可能，但也意味着模型拿不到绝对音高。论文提到有音高区域控制机制来补，但正文没展开细节。
- **参数量差距未被讨论。** Vevo2 是 872M，TCSinger 330M，StyleSinger 42M，差一个数量级，Table II 里没有做参数量对齐的对照实验。
- **后训练的奖励模型来自语音领域。** 可懂度奖励模型是用 INTP 这个零样本 TTS 偏好语料训的，直接用到歌声上是否合适，论文没有验证。

## 对我意味着什么

- **「SVS 数据只有 288 小时」这个说法要加限定语。** 准确的说法是「**带标注的**公开歌声数据只有 288 小时」。放弃标注要求之后，可用数据是 7,000 小时起步，天花板是整个互联网的音乐。这条修正了我读完综述之后的判断。
- **「SVS 那边没人做 RL」这条判断错了，要修正。** 我在综述那篇的笔记里写过这是学姐领先的空白，Vevo2 用了 GRPO，和她系统用的是同一个算法。空白存在于赵洲组那条线，不存在于整个领域。见 [[rlhf]]。
- **路线之争现在有两条清晰的线。** 一条是精标注加小数据加精细控制（赵洲组），一条是无标注加大数据加统一建模（Vevo2）。**Melody-MOS 那个输赢就是这两条路线的分界点：用旋律精度换数据规模和任务通用性。** 后面读 SVC 和 TTS 时可以一直用这个二分去归位。
- **色度图是音高表示这条轴上的一个全新答案。** 它既不是乐谱也不是 F0 曲线，而是去八度的音级能量分布。它的特性（去八度、免记谱、跨音色鲁棒）直接决定了这篇能用多少数据。见 [[pitch-representation]]。
- **约束和数据量是耦合的。** 前面五篇所有的折腾都是在「必须要乐谱」这个约束下的优化，TCSinger 2 把约束推到极限也只做到 268 小时。**当优化一个约束到了尽头，值得问的是这个约束本身能不能删掉。** 这条比任何具体技术都通用。
- **后训练的性价比。** 9K 步让歌声 WER 砍半，而预训练是 500K 步。凡是预训练完的模型在某个具体能力上不稳，先想后训练而不是加数据重训。
- **跟学姐工作的接口，这篇是目前最近的一篇。** 她的系统也是自回归规划加流匹配渲染两阶段，也用 GRPO 后训练，也做全曲级音乐。而色度图 token 提供了一个她可能用得上的东西：一种不依赖记谱、能同时描述人声和乐器旋律的统一表示。她的 two-level melody module 解的是同一个问题（粗轮廓加细节音高），色度图是另一种解法，值得放在一起比。
