#### 响度 / 电平
- **风险**:两批母带响度不同,分类器可能只在分"谁更响"。
- **怎么关的**:预处理统一 **LUFS −23** 归一化;
- **验证**:低层诊断里 `rms` 单特征 EER **45.78% ≈ 瞎猜** → 响度已不携带任何类别信息。
- **残留边界**:归一化只统一整体响度,**动态范围/压缩量**(crest、DR)没统一——但那属于制作差,
  归管,不另立案。

#### [[风格混淆]]

#### 人声 / 器乐
- **风险**:一侧人声多 → 检测的是"有没有唱"。
- **怎么关的**:round-1 **两侧都只用 instrumental**(FMA `track_instrumental==1` 6,045 首;Suno 器乐类)。
- **注意**:这是 round-1 的简化。将来扩到含人声时要重新对齐人声比例(到时再立案,现在不管)。

#### 人类标签纯度
- **风险**:"人类"集里混进 AI(标签污染,事后无法修)。
- **怎么关的**:人类侧 = FMA,目录 **2008–2017**,早于生成式音乐时代 → 构造上干净;
- **附带决定**:Pixabay 这类现代免费站因 AI 混入 + 禁爬,**判死不用**

#### 数据划分泄漏
- **风险**:近重复样本跨 train/test → EER 虚低。
- **怎么关的**:Suno `_1/_2` 同一次生成的两首**按 UUID 绑同一 split,0 对泄漏**;
- **验证([phone])**:打乱标签 sanity check 已跑——shuffle 后**全层 49–54% ≈ 瞎猜** →
  无隐性泄漏,所有实验结果可信。
- **残留小尾巴**(不急):FMA 按单曲分组,同艺术家可能跨 split → 大规模重跑时改成按 artist 分组。

#### >8kHz 高频 / 带宽
- **风险**:Suno 带宽更满(8–11kHz 比 FMA 高 ~+7dB),探针可能只在听"有没有超高频"。
- **怎么关的**:[[带宽匹配]]([phone])——两类同低通 8kHz 重抽重探针,
  EER **纹丝不动**(0.11–0.89% → 0.22–1.11%)→ 超高频内容不是驱动力,排除。

#### 编码历史 / 压缩痕迹
- **风险**:Suno 平台 mp3(固定 192kbps)vs FMA 各年代杂牌 mp3,压缩痕迹烙在波形里,
  FLAC 出口抹不掉([[Cros Vila 2025]] 实锤过这类平台管线捷径)。
- **怎么关的**:[[编码历史检查]]([phone])——两类同过 mp3 128k 往返"洗牌",
  EER **完全不动**(最佳层 0.11%)→ 编码链差异排除。

#### 亮度 / 频谱倾斜(全频段)
- **风险**:Suno 在 2–8kHz 平均亮 +4~6dB(低通 8k 砍不到的频段内倾斜),
  探针可能只在听"谁更亮"。
- **怎么关的**:[[频谱包络匹配]]([phone])——每首 EQ 到同一全局平均谱形
  (纹理保留,烟测包络差 1.29→0.04),EER **纹丝不动**(匹配后最佳层 0.33%)→
  **亮度假设彻底排除**;至此年代混淆的所有"便宜载体"清空,信号确认为宽带时频纹理,
  剩余假设(深层制作纹理 vs 生成指纹)交由跨生成器测试裁决,见 [[生成器混淆]]。

#### 处理历史对称(demucs 一刀,[phone])
- **风险**:SONICS 假歌过了 demucs 伴奏分离,若对照真歌没过同一刀,"有无 demucs 刀口"
  本身成为真假捷径(同编码历史检查的逻辑)。
- **怎么关的**:fma-test 450 + suno-test 450 的**原曲**用同参数过同一版 htdemucs
  ——两个测试类共享全部处理历史;suno_ref 兼职"汇率桥"量刀口代价。
- **验证(Batch 7b)**:域内过刀后 MuQ 0.22→0.33%、MERT ~1.9→2.44% → 刀口近乎免费,
  devocal 附表可信。
- **原则沉淀**:任何对一类做的处理必须同参数施于另一类——这是第 9 个被主动堵死的捷径。
