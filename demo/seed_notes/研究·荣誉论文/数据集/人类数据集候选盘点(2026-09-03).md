**人类数据集候选盘点([phone],第一幕 v2 用;后台文献/文档查证,未下载任何数据)。
目的:人类侧凑够 ≥12 个数据集,每个带齐对齐轴元数据(年代/genre/标签或描述/人声标注/许可),
全部入库前过 E13 式账号审计。已在用:FMA(2008–17)、jamendo2025(2024–26)、ccMixter、IA netlabels。**

1. **MTG-Jamendo**(主池;55,525 整曲,87 流派+40 乐器+56 情绪标签,含发行日期;2019 前冻结,污染低;有 voice/instrumental 字段)
2. **JamendoMaxCaps**(主池;202k 器乐整曲 + LLM 生成字幕;含 2023–24 上传,按 releasedate<2023 切层;与 jamendo2025 有重叠需去重)
3. **Jamendo API 2018–2022 逐年层**(填 FMA 与 jamendo2025 之间的年代空档;"AI 前最后清洁层")
4. **MusicCaps**(外验;5,521 × 10s 专家字幕;音频需 yt-dlp、部分失效;**已有 AI 对照 FakeMusicCaps/SunoCaps**)

## 排除与陷阱
- 排除:GTZAN(版权+错标)、IRMAS(3s 过短)、PMEmo/Music4All(商业版权/人声)、MSD/AcousticBrainz(无音频)、
  YouTube-8M/AudioSet(MusicCaps 已覆盖)、FSD50K(非曲目)、NSynth(非音乐)、Bandcamp CC(需自爬+ToS)、
  IMSLP 录音(部分是 MIDI 合成,需人工甄别);
- **合成陷阱**:Slakh/Lakh、NSynth、IMSLP 部分上传为 MIDI 渲染——不是人类演奏,勿混入人类侧
  (Slakh 可作"MIDI 渲染"对照组);URMP 是真人分轨录后对齐,可用但注明;
- 字幕来源三档:人写(MusicCaps、Song Describer)> 众包标签(MTAT、MTG-Jamendo、OpenMIC)> LLM 生成(JamendoMaxCaps)。
  反推 prompt 建议对 MTG-Jamendo 用 LP-MusicCaps 式模板把标签拼成句子,避免 LLM 幻觉;
- 人声过滤:MTG-Jamendo/JamendoMaxCaps/Jamendo API 有官方字段;MTAT 有 no-vocals;stem 集按 vocals 轨能量硬筛;其余自跑人声检测。

## 与"人类标签反推生成"直接相关的前作(deck 与论文必须引用/对比)
- MusicCaps → FakeMusicCaps(5 开源 TTM,27,605 × 10s)与 SunoCaps(64 曲 × 4 变体);
- FMA → **Echoes**(300 首 CC 原曲,GPT-5 描述,**12 生成器含 Suno/Udio**,CC-BY-SA;arXiv 2603.23667);
- MTG-Jamendo → **AIME**(500/6,000 真曲 vs 12 生成源;arXiv 2601.13647)。
→ "拿人类曲目的描述去让多家生成器生成对照"这个做法已有人做(Echoes/AIME),我们的差异要落在:
  同 prompt 协议的规模与家族覆盖、人声/器乐口径、E13 式审计、以及用它做**特征级**(非检测器级)对照。
